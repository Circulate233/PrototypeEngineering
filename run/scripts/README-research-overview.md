# 研究总览与研究场景示例

示例 mod 的 Java 注册提供三页、25 项实际研究：`pe_run_tests` 原有五项 Java 研究，`pe_demo` 将 HTML 的十四项研究接入真实注册表，`pe_showcase` 增加六项长列表、流体、多奖励和阶级切换示例。使用标准 CT 测试入口 `run/start-tests.ps1` 时，原 ZS 另注册 `research_manual`、`research_mutex`、`research_station`、`research_loop`、`research_special` 五项，合计三页 30 项；这五项脚本场景及下文原网络演示需要该入口。无 CT 的启动配置保留 25 项 Java 研究，新增研究不依赖这五项脚本定义。服务器从 `run/config/prototype_eng/research_content/data/` 读取名称、图标、说明、奖励组文字和分页布局。客户端从当前语言目录读取文字覆盖。新增研究由 `ResearchOverviewExamples.java` 注册，列出的状态需在游戏中推进。

从项目根目录执行 `run/prepare-tests.ps1` 后，用户完整启动客户端；新增机器与研究不能仅靠 `/ct reload`。关闭其它界面后按 **R** 打开玩家总览。管理员可执行 `/pe research edit` 为自己打开，或 `/pe research edit <在线玩家名>` 为对方开启本次编辑会话（目标无需 OP，控制台须指定玩家）；选中研究后用详情中的研究按钮立即完成下一级；普通研究仍需真实材料、时间、前置、设备与权限。右上角按钮切换自动/手动布局，仅手动模式允许长按研究拖动，切回自动立即重排；“全部导出”一次保存所有分页。队伍调试按钮可遗忘或完成全体成员（含离线成员）的全部普通研究，保留奖励记录。普通模式和编辑模式读同一份实际队伍数据，建议使用单独的测试存档，避免编辑完成后无法再观察未完成状态。

## 准备设备和材料

先按[网络演示](README-network-demo.md)搭建、供能并持续为网络计算机供水。原 CPU、量子与 IO 三种组件提供网络算力、量子位、内存、带宽、存储吞吐和信号处理；再把 `kit research` 提供的 `pe_run_tests:computer_card` 放进第四个运算仓槽，额外提供普通算力。普通算力与网络算力是两个独立资源，不能互相替代。新示例二级研究站可以消费全部七种非内部资源，二级数据库有 64 个研究条目容量。

```text
/pe_examples kit research
/pe_run_tests net-stock 5 80 0 pe_run_tests:computer_card 1
/pe_examples build overview_station_2 30 80 0
/pe_examples build overview_database_2 36 80 0
/pe_examples charge 30 80 1 1000000
/pe_run_tests net-stock 29 80 0 minecraft:iron_ingot 128
/pe_run_tests net-stock 29 80 0 minecraft:gold_ingot 64
/pe_run_tests net-stock 29 80 0 minecraft:redstone 512
/pe_run_tests net-stock 29 80 0 minecraft:paper 128
/pe_run_tests net-stock 29 80 0 minecraft:quartz 64
/pe_run_tests net-stock 29 80 0 water 4000
/pe_run_tests net-stock 29 80 0 lava 1000
```

二级站的输入仓在控制器西侧 `(29,80,0)`，输出仓在东侧，能源输入仓在南侧 `(30,80,1)`。手动研究从玩家背包扣取材料，站点研究从同队合格研究站输入扣料，不能把两种材料来源混为一处。`kit research` 提供设备、普通算力卡和一组基本材料，不会为 32 材料综合研究自动填满仓室。可以用上面的 `net-stock` 逐种补料；每次插入仍会检查真实仓室容量。

四张不同组件的原始并发合计 18，单台计算机限为 8；基础冷却合计 2,000/t、FE 合计 80/t。没有维护折扣且只用水时，3 mB 一份的转换每 tick 取 2,001 mB；维护成功 TICK 的冷却折扣生效后组件需要 1,800 冷却，另付维护配方自己的水消耗。有成型演示数据库时，网络事件把组件 FE 合计降为 72/t。供水和能源必须持续补充，命令中的有限存量只适合短时检查。计算机限额分别为普通算力 1,000、网络算力 800；第四槽已有额外 CPU 时，先将该 CPU 取出，再放普通算力卡。

二级库可能被选为同队活动数据库，原一级库保留为备用。右上应分别显示同阶数据库的已存条目/总容量，中心和最高研究站显示实际当前生效等级。用一级库和二级库各自的“选择研究”按钮对照处理阶级限制；选中后返回原库，而不是跳到活动库。

## HTML 的示例扩展页

`pe_demo` 初始为手动布局，十四个节点的作者坐标与 HTML 相同。按从左至右的分支逐项观察：

| 研究 ID | 名称 | 主要场景 |
| --- | --- | --- |
| `pe_demo:basic_circuit` | 基础电路 | 阶级 0 手动投料，三分支共同根节点 |
| `pe_demo:data_storage` | 数据存储 | 普通材料和算力累计，连接制图与逻辑门阵列 |
| `pe_demo:signal_amp` | 信号放大 | 0.5/t 的小数信号处理需求 |
| `pe_demo:high_heat` | 高能熔炼 | ITEM_ONLY 队伍直属等级，研究站研究但无网络资源 |
| `pe_demo:cartography` | 制图 | 纸材料加独立存储吞吐累计 |
| `pe_demo:logic_array` | 逻辑门阵列 | 两个同页前置汇合，算力和内存两项资源，完成后两组奖励任选其一 |
| `pe_demo:crystal_resonance` | 晶体共振 | 阶级 2 研究，一级设备不足时的不可用状态 |
| `pe_demo:refining` | 精炼工艺 | 普通单前置分支，继续解锁互斥与多级研究 |
| `pe_demo:quantum_link` | 量子缠绕 | 同页前置加跨页 Java 高速连接 Lv.1，阶级 2，单组奖励 |
| `pe_demo:optical_link` | 光学传输 | 与黏性封装互斥，带宽累计 |
| `pe_demo:sticky_seal` | 黏性封装 | 与光学传输互斥的另一分支 |
| `pe_demo:alloy` | 合金工艺 | 最多三级，第二级起升为阶级 2，逐级增长算力，仅第 1 和第 3 级有奖励 |
| `pe_demo:enchant_theory` | 附魔理论 | 需要制图 Lv.1 与合金工艺 Lv.2，指定等级的多前置 |
| `pe_demo:gemology` | 宝石学 | 开始、移出保留进度、重新加入继续研究 |

可先在普通模式完成基础电路，观察前置未满足节点变灰、点击无反馈及悬停列出的还需研究。继续完成数据存储和信号放大后，再打开逻辑门阵列，检查汇合折线和双前置状态。量子缠绕还要求“运行测试”页始终由 Java 注册的高速连接 `pe_run_tests:java_research_connection` Lv.1，跨页前置显示短虚线和所在分页名称。

完成光学传输后，黏性封装应显示互斥阻止。若已在编辑模式完成两者，应把该存档作为冲突状态示例使用，不再当作普通解锁顺序。完成合金工艺 Lv.1 后用一级库选择它，再升到 Lv.2、Lv.3，比较一级库可处理的等级和二级库的完整等级；等级与研究阶级分别显示。

逻辑门阵列完成后先不领取，打开详情检查两组待选奖励。选中“电路套件”或“研究资料”后领取，只能得到一组；关闭重开检查“已领取”。合金工艺第 2 级没有奖励，第 1 和第 3 级的奖励资格各自保留，不应因继续升级丢失。

## 研究万花筒页

`pe_showcase` 初始使用自动布局，六项研究互不要求前置，方便单独入队或在编辑模式立即完成。

| 研究 ID | 名称 | 主要场景 |
| --- | --- | --- |
| `pe_showcase:long_catalog` | 超长综合研究示例 | 超长名称、五段说明、32 种材料、16,384 红石、六种网络资源，详情与研究站分别滚动 |
| `pe_showcase:fluid_analysis` | 流体分析 | 水 4,000 mB、岩浆 1,000 mB、纸 8，`kind=fluid` 水图标 |
| `pe_showcase:reward_gallery` | 奖励展示厅 | 短手动研究，三组奖励任选其一；“野外物资”的十二种物品自动换行，“命名勘探工具”用注册的自定义类型逐行显示镐、弓和各自名称，并保留原 NBT |
| `pe_showcase:manual_chain` | 手动研究笔记 | 三级手动研究，逐级更换材料、时间与奖励；暂停、接管、缺料和保留进度 |
| `pe_showcase:tier_transition` | 从笔记到实验室 | Lv.1 手动、Lv.2 一级站、Lv.3 二级站，当前卡片随研究类型变化 |
| `pe_showcase:empty_research` | 安静观察 | 无普通材料、无网络资源、无奖励的一级研究站任务，`kind=icon` AE 帮助图标 |

超长综合研究的材料如下：铁锭、金锭、红石、煤、下界石英、染料、纸、书、玻璃瓶、线、皮革、羽毛、燧石、黏土球、红砖、地狱砖、荧石粉、火药、糖、黏液球、末影珍珠、烈焰粉、岩浆膏、恶魂之泪、蜘蛛眼、发酵蛛眼、海晶碎片、海晶砂粒、兔子皮、兔子脚、骨头、小麦。红石总量 16,384，其余每项 32～38；具体值直接看详情或 Java 注册，不用一次塞满背包。它消耗算力、量子位、内存、带宽、存储吞吐与信号处理，缺任意一种时保留其它资源的独立累计进度。

奖励展示厅只需玩家背包中有 4 张纸。选择物资组可检查十二种奖励物品的多行槽位；选择工具组可检查命名 NBT；选择宝石组检查精确件数。这三种互斥选择应分开用不同测试角色/存档观察，不能通过重复领取同一次奖励来切换。

手动研究笔记的三级依次需要铁锭 4、金锭 4、绿宝石 2，时间分别为 100、160、220 tick。先只放部分材料，检查剩余需求；取消“消耗背包中的物品”后应暂停并保留进度，另一队友可以接管。完成多级后再领取，检查三张独立奖励卡。

从笔记到实验室第一级用纸 8、100 tick，第二级用铁锭 8 和算力 1,000、200 tick，第三级用金锭 8 和算力 3,000、300 tick。第二级开始时不再显示手动投料开关，改为真实研究站数量和可用材料；移除二级站或让其缺电后，第三级会等待合格设备。

## 状态与交互组合

| 检查对象 | 实际操作 | 应观察的行为 |
| --- | --- | --- |
| 空队列 | 将队列全部移出 | 五个空圆槽保留，当前研究卡片隐藏 |
| 满队列 | 加入五个可开始的不同研究 | 圆槽序号、队首进度及研究站队列一致，第六项不可加入 |
| 排序 | 选队尾“设为当前”，或在研究站上/下移动 | 同队共享顺序变化，圆槽点击定位正确分页 |
| 缺材料 | 只投入少量普通材料 | 红色不足数量，已付款与已累计进度不倒退 |
| 缺网络资源 | 取走计算组件、停止冷却供给或启动普通负载机 | 研究等待剩余资源，不伪造完成；补齐后继续 |
| 出队与续研 | 部分推进宝石学后移出，再加入 | 保留百分比和剩余需求 |
| 已完成/部分等级 | 完成合金第一级或全部三级 | 节点配色、等级徽标和详情内容区分部分与最高完成 |
| 已下载 | 将完成研究下载到数据库 | 黄色标记与已下载提示，不能重复写入相同或更高已存等级 |
| 遗忘 | 对有个人等级的研究打开遗忘确认 | 预览依赖等级与队列变化，取消无变更，确认只执行所选等级起的遗忘 |
| 特殊研究 | 查看原有 `pe_run_tests:research_special` | 不能普通入队/选作物品下载；研究盘导入按原演示流程验证 |
| 无设备/阶级不足 | 去掉中心、研究站或改用一级库 | 不可用原因及右上设备等级反映真实状态 |
| 语言与图标 | 切换简体中文/英语，重载客户端资源 | 英文基础内容与中文字段覆盖正确，物品/流体/AE 图标均可显示 |
| 全屏与滚动 | 更换 GUI 缩放，拖动画布、滚轮缩放、拖详情滚动条 | 面板比例保持一致，正文不盖轨道，JEI 叠层隐藏，固定底部按钮可点击 |
| 关闭重开 | 切到非首页、平移并缩放后关闭，再打开总览 | 有效分页与视角恢复；窗口调整尺寸不重新载入旧位置，作者分页文件不变 |
| 材料与保存 | 手动研究和研究站分别连续投料推进 | 材料按原比例开放时间，付款前后继续推进；支付、完成与退出重进均无丢料或重复扣料 |

编辑模式还提供右键菜单：在空白处添加分页、从已注册研究中向当前页添加研究；手动布局的新节点放在右键位置，自动布局会重新排列。研究已归属其它分页时，添加操作会把它移动到当前分页。右键节点可编辑服务端基础 `data` JSON，也可从游戏支持语言的下拉列表选择语言，在客户端保存名称、说明和奖励组文字。材料、时长、前置和奖励定义仍由 Java/ZS 注册。拖动手动节点时允许重叠，点击“全部导出”统一保存所有分页的服务端布局。

验证隐藏规则时，可以在测试服务端的 `data/pe_demo/data_storage.json` 中加入 `"visibility": "after_prerequisites"`，再将 `pe_demo:cartography` 单独放到一个 `priority` 更小的新分页。基础电路解锁前，数据存储及依赖它的制图均不显示，制图分页也隐藏；完成基础电路后，这两项及制图分页应出现。把数据存储改为 `after_completion` 时，完成数据存储第一级后才显示。授权编辑会话可查看和编辑隐藏研究与空分页。

上述内容只说明可操作场景。编译、独立 SDK 检查和静态坐标核对不代表真实世界、多人权限、持久保存或 OpenGL 已验收；实际观察由用户完整启动后进行。
