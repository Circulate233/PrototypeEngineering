# ME 总成、隔离与连接纹理示例

这批场景使用当前 PE 的实际方块、ME 节点和事务接口。先在项目根目录执行 `run/prepare-tests.ps1`，然后由用户完整重启开发客户端；新增类型在 preinit 注册，单独 `/ct reload` 无法加载它们。

## 先快速查看全部方块的连接纹理

在已加载、可修改且没有建筑的空地执行：

```text
/pe_examples build ctm_gallery 0 80 0
/pe_me_examples gallery-check 0 80 0
/pe_me_examples gallery-list 0 80 0
```

`ctm_gallery` 是真实注册的结构，控制器 ID 为 `pe_visual_examples:ctm_gallery_controller`。内容在启动时从 Forge 方块注册表生成，覆盖所有 `prototype_eng` 方块，包括十五种装饰、全部材料/能源仓等级、四种 ME 总成、五阶并行组件和研究等正式组件，并加入本批 Java/ZS 示例并行组件。后续新增的 PE 方块会自动进入同一检验场。

每种方块有 **27 格**：3×3 地面、3×3 后墙及3×3 侧墙，三面相接。可同时观察墙面中间、四边、四角、上下接缝、垂直转角及玻璃相邻面的隐藏。各类型之间留有空隙；同类连续铺设，便于比较实际 CTM 与基础纹理。场景不自动放材料、供能或连接 ME 网络。

一行八个展台，每台步长五格。朝北布局时，第 `i` 个展台（从0起）的地面起点相对控制器为：

```text
(3 + (i % 8) * 5, 0, 3 + (i / 8) * 5)
```

场景宽度最多42格，高4格，深度随注册数量变化，约为 `3 + ceil(种类数/8)*5` 格。总材料为 `27*种类数+1`，包括原点控制器。预先检查所有目标位置；存在占用或未加载区块时整次拒绝，不替换建筑。`build` 也接受原有朝向参数，坐标查询和覆盖检查会使用实际控制器朝向。

`gallery-list` 列出每种方块 ID 和展台地面起点；`gallery-check` 只验证已加载的实际方块与来源清单一致。请飞到玻璃、外壳和通风口墙面两侧观察、尝试资源重载，并查看实际CTM/Bloom画面。源三图现由PE注册的47状态CTM类型接通，库存使用独立基础面；请完整重启加载新类型后验证。生成检验场不代表连接效果已通过实机验收。

## 六个可运行的 ME 场景

```text
/pe_examples kit me
/pe_examples build me_assemblies 0 80 70
/pe_examples build me_interface 10 80 70
/pe_examples build me_pattern 20 80 70
/pe_examples build me_colors 30 80 70
/pe_examples build me_parallel 40 80 70
/pe_examples build me_wide 50 80 70
```

也可使用完整 `pe_run_tests:` 前缀。kit发放六种控制器、检验场控制器、装饰和仓室、七种并行组件，以及 AE 控制器、创造能源单元、驱动器、物品/流体存储元件、电缆和普通/PAT/编码终端。背包放不下的物品掉在玩家身边。样板合成测试还需自行搭建真实 AE 合成 CPU。

| 场景            | 控制器相对位置（朝北）                                                      | 实际配方与观察目标                                                                                     |
| --------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `me_assemblies` | 西 `(-1,0,0)` 输入总成，东 `(1,0,0)` 输出总成，上 `(0,1,0)` 外壳            | 铁锭2→铁粒9，80tick；沙2+水250mB→黏土球1，100tick。输入/输出位可换为机械接口。                         |
| `me_interface`  | 西侧机械接口，上方外壳                                                      | 同一实际接口的输入与输出两个缓存完成上面的两条配方。                                                   |
| `me_pattern`    | 西侧样板总成，上方外壳                                                      | 框架外皮控制器；单独铁、金样板与共享红石催化剂；额外合并配方用于观察跨样板隔离。                       |
| `me_colors`     | 西 `(-1,0,0)`、西后 `(-1,0,1)` 两个四阶输入；东及东后两个四阶输出；上方外壳 | 铁锭4→钻石1，80tick；不同颜色的2+2不能合料，同色可以。                                                 |
| `me_parallel`   | 西输入、东输出、上外壳、后 `(0,0,1)` 普通并行控制器                         | 铁锭1→铁粒9，200tick；内部贡献1，额外组件相加，整机上限1024。                                          |
| `me_wide`       | 与输入/输出总成场景相同                                                     | 煤1→铁粒2,147,483,648+水9,000,000,000mB；沙1→16色羊毛、混凝土、染色玻璃各1，共48种输出。两条均80tick。 |

新场景自身不消耗 FE；ME 网络仍需要真实 AE 供能、频道和存储空间。搭建命令给实际 AE 方块实体设置放置玩家归属。

## 目标补足、接口和大缓存

给输入与输出组件分别接电缆；一小套独立网络足够测试，更多组件可连接到控制器分支。把物品元件和流体元件装入驱动器，使用真实终端把材料存入 ME。

输入总成与接口共用输入槽数配置，默认18。手持物品左键设置标记，手持水桶右键选水；中键打开 AE long 编辑页，Shift/Ctrl＋滚轮调整数量。也可显式设置零起始标记：

```text
/pe_me_examples mark -1 80 70 0 minecraft:iron_ingot 2
/pe_me_examples mark -1 80 70 0 clear 0
/pe_me_examples mark -1 80 70 0 minecraft:sand 2
/pe_me_examples mark -1 80 70 1 water 250
/pe_me_examples inspect -1 80 70
/pe_me_examples mark -1 80 70 1 clear 0
```

先只设置铁标记观察干配方，再清除标记并换成沙和水观察湿配方；按想验证的分支依次执行，不必一次粘贴整组命令。标记上方显示期望量，下方显示实际缓存。

机械接口输入在上、输出在下；输出总成没有标记。输入与输出的实际缓存由 ME 与机器事务转移，`/pe_examples stock` 对这些 ME 总成明确拒绝。可从输出组件的 `inspect` 查看真实输出种类数；实际只读槽也应拒绝手动塞入。

大缓存测试时，只在输入网络放煤1或沙1，并让输出总成保持断网，避免输出立刻退回 ME。煤与沙分别测试，煤样例中不可把水再乘1000。48种输出超过当前40格输出窗口，应能滚动看到全部内容。之后给输出总成接上真实 ME 网络，观察按网络接受量逐步清空；网络容量不足时剩余材料留在总成。参数编辑可输入 `9223372036854775807` 检查长整数显示，先用少量真实材料验证补足行为。

## 颜色库存隔离

所有资源仓默认福鲁伊克斯色，即无色（`TRANSPARENT`）。无色是独立库存，各有色组都可以通用读取；不同有色组仍不能互相拼料。先按下面命令显式把前排设红色、后排设蓝色，再投料验证隔离：

```text
/pe_me_examples color 29 80 70 RED
/pe_me_examples color 31 80 70 RED
/pe_me_examples color 29 80 71 BLUE
/pe_me_examples color 31 80 71 BLUE
/pe_me_examples assert-groups 30 80 70 2
```

分别在两输入仓手动放铁锭2。预期控制器不能付款；两边均保留2。通过普通仓GUI把前排的铁取出，或把前后输入/输出全部设为相同颜色再观察。都设红色后，四个铁可以支付一条配方，红组输出钻石1。输出可用同色仓或通用无色仓。

再把前排输入改为 `TRANSPARENT`，后排仍为蓝色，各放铁锭2，应可使用无色2＋蓝色2支付。无色库存仍只保存一份，不能被其他组重复扣除；GUI颜色面板下方的福鲁伊克斯色按钮可随时设回无色。

`/pe_me_examples inspect <控制器坐标>` 在真实宿主边界列出当前组、颜色/分区、并行上限及运行进程 UUID。保存退出、重新进入后，已运行配方仍按原颜色/分区恢复，不跨组借料。

## 样板总成、共享催化剂与 PAT

```text
/pe_me_examples patterns
/pe_me_examples color 19 80 70 RED
/pe_me_examples inspect 19 80 70
```

命令从当前实际配方构造三张 AE 加工样板：

| 样板输入（ME提供） | 机器额外读取的共享催化剂 | 输出  |
| ------------------ | ------------------------ | ----- |
| 铁锭1              | 红石1                    | 铁粒9 |
| 金锭1              | 红石1                    | 金粒9 |
| 铁锭1+金锭1        | 红石1                    | 钻石1 |

把铁与金两张样板放入不同样板槽，红石放入催化剂区；红石在本示例配方中每次消耗1，未声明可重复使用。先在空缓存、没有运行配方时切换“样板隔离”模式，由真实 AE 合成请求投入。总成设为 `TRANSPARENT`、`RED` 或 `BLUE` 都应保持逐槽独立：每个槽读取自己的 ME 输入、该总成公共催化剂以及结构中其他未分区无色输入仓。额外的合并配方不能从两个样板槽各借一种材料，也不能从同色普通仓借料；把第三张合并样板单独放入一个槽则可正常工作。

原`me_pattern`结构不含外部输入仓，可直接验证铁、金两个槽不能合成钻石，以及三种总成颜色均不合并槽位。外部仓供料需另行声明同时包含样板总成和输入仓的结构；只在附近摆仓不会被扫描为结构成员。在这种结构中，向无色仓提供缺少的材料，应可由单个样板槽加无色库存完成合并配方；把外部仓设为有色后，应再次无法借用它的材料。保存重进后仍应绑定原样板槽；未开启槽隔离时才按总成颜色参与普通颜色分组。

默认、阻挡、配方阻挡、样板隔离、合成锁定五模式在左键松开时循环，右键松开打开AE选择器；按住按钮不改变模式，拖出松开取消。每页36槽，`config/prototype_eng/me_assemblies.cfg`的`patterns.pages`控制新放置总成页数。批量×/÷2、3、5、8逐槽处理，不可整除、无效或溢出的槽保持原样，其余继续修改。

催化剂区放入普通物品，再空手左键取出一组、右键取出半量；鼠标不移开也应只执行一次，不回弹、不自动封包。非物品使用对应容器右键倒入、左键装填，Shift批量存取。分别比较可用/不可用滚动条、标题居中和分行帮助；把有样板/AE资源包的物品放在普通仓/样板总成旁边，反复查看背包及JEI，核对后绘制的方块图标不再随着前一个物品而变暗。

将 PAT 接入同网后，核对总成名称、分组、可见性、样板编辑、远程打开及Esc返回；走到8格之外仍应仅在原终端会话和同网节点有效时保持远程窗口。合成 CPU 仍拥有合成任务；总成按真实供料进程 UUID 管理合成锁。多数量请求用于观察 AE2S 合并输入，不能用开发命令直接向实际输入缓存塞材料代替网络请求。

## 七种并行组件

`me_parallel` 的后方组件位接受五阶内置控制器，以及 Java 和 ZS 两种外部注册示例：

| 组件                               | 默认最大贡献            | 加内部1后的上限         |
| ---------------------------------- | ----------------------- | ----------------------- |
| 普通 / 强化 / 精英 / 超级 / 终极   | 4 / 16 / 64 / 256 / 512 | 5 / 17 / 65 / 257 / 513 |
| `pe_visual_examples:parallel_java` | 24                      | 25                      |
| `pe_run_tests:parallel_zs`         | 32                      | 33                      |

Java示例通过真实 `ParallelControllerRegistrationEvent` 注册，ZS示例位于 `13_pe_run_me_preinit.zs`；两者省略模型参数，采用保留的原始单纹理。内置五阶使用独立PNG。若修改过配置，以实际组件GUI的上限为准。

```text
/pe_me_examples inspect 40 80 71
/pe_me_examples assert-parallel 40 80 70 5
```

右键组件改变当前贡献，设0时整机贡献变为1。正常投料后调整组件，应仅影响后继准入；已运行进程保持原数量。检查大等级时要投入足够原料并留出输出空间，`assert-parallel` 检查的是结构贡献上限，实际批次数仍受材料与事务约束。

## 验证边界

Java编译与真实SDK脚本编译可以在不启动游戏的环境中验证。ME网络、PAT操作、实际合成CPU、CTM/Bloom、世界搭建和退出重进均需用户在开发客户端执行。检验场覆盖检查通过只说明真实方块齐全，不代表连接纹理图像已经正确。

## 2026-11-12 按钮、轨道与分层物品复验

- 普通材料仓自动IO保留原14×14图与位置；颜色按钮使用同款小框，挂耳延伸不覆盖上方IO。左/右松开执行、拖出取消。
- ME输入/输出与接口分别检查轨道顶端、底端、不可滚动状态；内轨x175，单仓y25，接口上y25/下y98。滚轮、按轨和拖动应与普通仓同样连续，最后不足整行的标记/真实资源仍可到达。
- 用普通、ME、能源仓及机械电路块对比背包/HEI，分别看机械外壳底层和发光覆盖层。HEI通过本库ItemBlock公开marker改走原生Forge渲染，专查覆盖层不再因格式转换的零法线而发暗。原生库存若仍出现局部层差异，应记录具体方块和层；本轮未运行GL，不把离线合成预览当作游戏结果。
