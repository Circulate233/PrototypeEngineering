# 研究总览界面与服务端目录

[research-overview.html](previews/research-overview.html) 展示总览的布局。配置、同步及操作规则以本文为准，实现状态与验证证据见 [implementation-status.md](implementation-status.md)。

库不注册玩家打开研究总览的按键或物品。提供玩家模式与数据库模式的打开方法，实际从物品、按键或其他界面调用由使用方决定；测试 mod 注册一个打开玩家模式的按键。管理员编辑模式保留专用服务器命令与授权检查。

## 打开入口

使用方通过 `com.circulation.prototype_eng.api.gui.ResearchGuiAccess` 打开总览：服务器侧 `open(EntityPlayerMP)` 打开玩家模式，`open(EntityPlayerMP, MachineControllerHost)` 以指定物理数据库打开选择模式；客户端按键或其他入口调用 `requestOpen()`，由服务器创建玩家模式容器。数据库界面的“选择研究”已通过容器调用数据库模式，选定研究或退出后返回原物理数据库，并保留其操作槽物品。

测试 mod 的打开按键默认是 **R**，可在游戏按键设置中修改；只有玩家存在且当前没有打开界面时才发送打开请求。库本身不绑定此按键。编辑模式使用 `/pe research edit [玩家名]`，要求命令执行者具有权限等级 2；不带参数时为执行者本人开启，指定在线玩家名时为该玩家开启，并提供玩家名补全。控制台使用时必须指定玩家。`openEditor(EntityPlayerMP)` 为管理员本人开启，`openEditor(ICommandSender authority, EntityPlayerMP target)` 为指定玩家开启；两者使用相同的管理员权限和同服检查。

被指定玩家无需 OP；管理员授权只绑定本次编辑容器。服务端在提供编辑数据、保存分页或基础文本、立即完成研究及写入特殊研究时检查当前容器、目标玩家和授权者。关闭或替换界面，或授权者离线、重连、失去权限后，授权失效。普通研究操作继续使用目标玩家自己的权限。

## 两种构造

研究总览是一个界面类，提供两个构造函数，两者共用画布、分页、节点和右侧详情，按构造参数切换可用操作。

使用玩家构造时用于研究。界面显示本队可见研究的完成情况和队列条目，玩家可以开始研究、调整队列、领取奖励、把已完成的研究下载到当前活动数据库，以及遗忘自己的个人等级。使用数据库接口构造时只用于为“下载到物品”选择研究，入口是数据库界面的“选择研究”按钮，选定后返回数据库界面；该模式不显示研究队列，也不提供研究、下载到数据库和遗忘按钮。

数据库模式可以选择任意队伍已完成、且研究阶级不高于打开界面的这台数据库阶级的研究，不要求研究已存于这台数据库。队伍等级使用服务器计算的有效等级（两种普通下载策略均取当前成员个人等级最大值，兼容旧直属等级；前置不足时回退）。研究阶级按已完成等级逐级判断：只要第 1 级的研究阶级不高于数据库阶级即可选择，更高等级的阶级高于数据库时，详情提示数据库只能处理到哪一级，实际下载配方和费用由数据库界面按服务端判定。未完成、第 1 级阶级过高和 `specialOnly` 研究不可选，变暗并且点击没有反馈，悬停说明原因。选择不检查研究是否已存于该数据库；`DATABASE_AND_ITEM` 研究未存入时，返回数据库界面后的操作区显示服务端实际状态（现有下载判定要求数据库已存该等级，见[数据库界面](research-gui.md#数据库界面)）。

## 全屏布局与画布

研究总览是全屏界面，画布铺满整个屏幕，没有外框窗口，所有面板直接悬浮在画布上。配色只使用 AE 界面已有的颜色：画布为 AE 面板色 `#9a9fb4` 加浅色网格线，悬浮面板为 AE 底色 `#cbccd4` 并使用四角封闭的原生 `ae2:textures/guis/background.png` 窗口边框贴图（256×256、九宫格源边宽 4 像素），槽位 `#adb0c4`，深色强调 `#413f54`，状态色使用研究站与数据库已有的绿、黄、红三组标签色，按钮使用 AE 原生按钮与方形图标按钮贴图。禁止使用深色背景主题或参考图中的橙色、青色等非 AE 颜色。全屏绘制与输入使用自己的连续虚拟坐标，不沿用玩家的 Minecraft GUI 缩放；原生界面边界仍覆盖屏幕，JEI 的侧栏、书签和设置按钮不得叠入总览。

各区域位置如下：
- 左上角：分页、研究队列和当前研究（见下文）。
- 顶部中央：斜纹提示条，玩家模式显示“队名 · 研究总览”，数据库模式显示“数据库名 · 选择下载研究”，编辑模式改为黄色并说明编辑操作。
- 右上角：玩家模式依次显示标题“数据库：”、各阶数据库“LvN 已存条目 / 总容量”、“网络中心：LvN”和“最高研究站：LvN”。数据库阶级从低到高排列，同阶本队全部已加载有效物理数据库（含备用数据库）的已存条目数与容量分别求和；一条已存研究占一个容量格，研究等级不额外占格。没有数据库时数据库区显示“无 0 / 0”，没有有效中心或研究站时对应等级显示 Lv0。不得添加活动数据库名称或活动状态行。数据库模式为 AE `Icon.BACK` 返回按钮；编辑模式在信息面板上方提供布局切换、“全部导出”与队伍调试按钮。
- 左下角不放内容，删除缩放比例与操作提示；滚轮缩放和拖动平移仍按原规则执行。
- 右下角：ESC 的当前作用。

右侧详情打开时，右上角和右下角内容随之左移，不被详情遮住。

HTML 的设计尺寸使用 CSS 像素；正式界面使用独立的 1536×864 参考画布，以 `min(显示像素宽 / 1536, 显示像素高 / 864)` 为统一显示比例，再把参考画布扩展到屏幕的实际长宽比。面板、按钮、队列和节点按下表 CSS 尺寸绘制，所有鼠标位置从实际显示像素连续映射到同一坐标系，拖动在每次绘制时更新；不得先经过 Minecraft 整数 GUI 坐标再换算，避免大 GUI 缩放导致整个界面放大、鼠标跳动。玩家的 GUI 缩放选项不改变总览的各面板比例。`S=1.7` 只保留为既有研究布局文件的作者坐标与 CSS 设计尺寸之间的换算（CSS = 作者坐标 × 1.7），下表最右列同样是该作者坐标，不是原生 GUI 缩放下的物理尺寸。屏幕宽度只影响边缘定位、页签换行及内容可见范围。界面字体使用实际 Minecraft 字体，超宽按原字号截断，完整显示的文字不得因小数误差被误判为超宽；不能通过放大按钮或移动按钮修补文字。

滚轮以光标位置为中心缩放，范围 50%～200%；按住左键在画布任意位置拖动平移，拖动距离超过 3 像素后不再触发点击。点击空白处收起右侧详情；ESC 先收起详情，没有详情时关闭界面，数据库模式下关闭即返回数据库界面。

总览在关闭时将当前分页 ID、画布平移和缩放写入客户端独立配置 `config/prototype_eng/client/research_overview_view.json`。下次打开时，等待研究分页与画布尺寸就绪，仅恢复一次；分页仍存在且数值有效时直接回到上次视角，分页消失或文件损坏时使用默认视角。窗口重新初始化不会再次覆盖当前拖动位置，不逐帧写文件。玩家、数据库选择与编辑模式共用该客户端最后一次总览视角；队列槽的主动定位仍可切换分页并居中。视角配置不写入研究内容、分页布局或导出文件。

## 研究节点

研究平时只显示方块和图标。方块颜色表示状态：已完成为绿底绿框，部分等级完成为绿底浅绿框，可研究为槽位色，当前研究为白底深色框，前置未完成为灰色并降低图标透明度，互斥阻止为红底红框，特殊研究为黄底黄框。多等级研究在右下角显示“当前等级/最高等级”，无限等级只显示当前等级。队列中的研究左上角显示队列序号，已下载到任一数据库的研究右上角显示黄色小方块。

当前研究和保留部分进度的研究，方块向右加宽，在图标右侧显示百分比。点击研究后节点向右展开为长框，显示名称和一行状态（多等级且未完成的研究显示“Lv.当前 / 最高”，其余显示状态文字）；带进度的研究额外显示进度条。名称超出长框时按原字号截断加省略号，完整名称在悬停提示和右侧详情中显示。同一时间只展开一个节点，再次点击或点击空白处收起。展开的长框被左上角面板或右侧详情遮住时，画布平移到刚好露出长框。

前置关系以折线连接：前置已满足为深色实线，未满足为浅色实线。连线由客户端按两端位置自动计算，分页文件不保存连线：从前置研究右侧水平引出，在目标研究左侧 8 像素处折向目标行；前置位于目标右侧或距离过近时，先向下或向上绕行再接入。跨分页的前置在研究左侧画一段虚线和空心圆点，悬停研究时在“还需完成”中写出所在分页名称。

## 左上角分页、队列与当前研究

分页紧贴屏幕顶边，从左上角开始横向排列。每个分页是固定宽度的标签：顶部一条贴住屏幕上沿的横条，横条下方居中显示大号分页名称，不显示图标或数量。当前分页的横条和文字为深色 `#413f54`，标签内有由上向下渐隐的浅色底；其他分页的横条为 `#878fa5`，文字为浅色，悬停时加深。名称超出标签宽度时按原字号截断加省略号；悬停显示完整名称和本页完成数（数据库模式为可选数量），编辑模式额外显示分页 ID 和名称键。分页超过顶部中央提示条左侧的可用宽度时换到下一行，左上角其余内容随之下移。

玩家模式在分页下方始终清楚绘制 5 个圆形队列槽，包括空槽，右上角标注已占用槽的序号，队首槽外圈按进度填充；不能因为面剔除或绘制顺序导致队列只剩悬空图标。点击任一队列槽切换到对应分页，把该研究移到画布中央并打开详情。队列槽下方只有存在当前研究时才显示当前研究面板；研究队列为空时整个面板消失，不绘制空框或“暂无研究”等提示。当前研究等待资源或手动研究已暂停时仍显示该研究与保留进度。数据库模式在分页下方显示数据库阶级、可选研究数量和可选研究规则，不显示队列。

队首为研究站研究时，当前研究面板显示研究名称、目标等级、参与研究站数、工作量进度条。行内风格沿用正式研究站：小标题左对齐、数量含义用次要文字色右对齐，名称左对齐、数值右对齐，进度条使用既有底色和完成/不足颜色。材料每种一行显示图标、名称和“剩余可用 / 剩余需消耗”，不使用材料网格；左侧汇总同队全部可用研究站的实际可供料量，并最多显示到右侧剩余需求。例如已付 2、总需 10、库存 20 时显示 8/8，库存只有 3 时显示 3/8，付清后显示 0/0。网络资源每项第一行显示名称与“占用 / 上限（/t）”，第二行显示累计细条，第三行显示“已累计 / 总需求”与百分比；累计完成使用绿色。队首为手动研究时显示投料玩家、研究时间进度、同样的材料“剩余可用 / 剩余需消耗”，以及“消耗背包中的物品”复选框：勾选表示由当前玩家接管投料，取消勾选暂停投料并保留已投入的材料与进度。手动材料的可用量来自当前贡献者实际可供料背包，遵守下载保护槽位规则；无人投料或贡献者不在线时为 0，不读取机器库存。不足的材料数字显示为红色。研究站界面查看同一手动队首时使用相同来源和封顶规则。

## 右侧详情

点击研究后右侧弹出竖向详情面板，贴住屏幕右边缘，高度占满屏幕。面板顶部为图标槽、研究名称、状态标签、等级标签和 AE 方形关闭按钮。正文依次显示研究简介与说明文字（来自服务端基础内容，支持客户端本地化覆盖）、当前目标等级的研究进度、研究信息（目标等级、研究阶级、研究时间、下载方式）、前置研究、互斥研究、目标等级的材料与网络资源，以及完成奖励。网络资源只列累计总需求；“单站上限”不属于研究定义，研究速度由实际研究站决定，不在研究详情显示。已达最高等级的普通研究不再显示材料与网络资源。

完成奖励显示已完成等级和下一级的奖励组。界面绘制标题、说明文字和领取状态，各奖励组的内容由收到的展示类型自行绘制。组合奖励按可用宽度换行，行高取该行最高子项。同一等级有多组时标注“任选其一”，未领取时点击奖励组选中，选中后才可领取；只有一组时直接领取该组。已完成未领取的等级显示“领取奖励”按钮，已领取显示绿色“已领取”，未完成显示“完成后可领取”。

研究、下载等操作按钮固定在面板底部。玩家模式下，不在队列中的研究显示“开始研究”（有保留进度时为“继续研究”）与“下载到数据库”；队首研究显示“移出队列”；队列中其他研究显示“设为当前”和“移出队列”。按钮下方一行显示下载状态。数据库模式只有“选择此研究”。

## 点击与悬停规则

悬停提示使用 Minecraft 原生 GUI 字号和鼠标坐标，由 Forge 处理光标偏移、换行与屏幕边缘避让。提示绘制前必须恢复总览画布的缩放矩阵，禁止把参考画布坐标直接传给原生 tooltip；否则提示及扩展渲染事件会使用不同的缩放和定位。

玩家模式下，前置未完成的研究点击没有任何反馈，不展开节点也不打开详情；悬停时列出还需完成的研究及等级。其余研究点击后展开并打开详情，包括已完成、互斥阻止和特殊研究，以便查看文字与奖励。

条件不满足的按钮显示为禁用状态，悬停在按钮上显示原因。“开始研究”按目标等级的研究阶级判定：阶级大于 0 的研究要求有网络中心、最高研究站等级不低于研究阶级，两项缺哪项就提示哪项（可同时提示多项），不满足时禁止入队；阶级 0 的手动研究不要求这些设备。开始、材料汇总与推进研究均不要求数据库，数据库阶级仅按下载等独立操作的规则检查。其余原因按服务器入队判定给出：互斥研究已完成、研究队列已满、已达最高等级、特殊研究不能入队；开始条件回调由服务器在点击时执行，界面不预先调用。设备条件不足的研究方块使用红色边框。详情的“开始条件”只显示网络中心与最高研究站，不添加活动数据库需求行；按钮缺少条件时沿服务端判定给出有用的禁用原因。“下载到数据库”的原因按数据库写入判定给出：尚未完成、只能下载到物品、特殊研究、没有活动数据库、研究阶级高于数据库阶级、容量已满、与数据库中的研究互斥；阶级按要写入的队伍等级计算，高于活动数据库阶级时不能下载。

下载到数据库不会重复。队伍任一数据库（含非活动数据库）的已存等级不低于队伍当前等级时，按钮禁用并显示“已下载到 数据库名（Lv.N）”；队伍当前等级高于所有数据库的已存等级时可以下载，写入活动数据库并更新已存等级，此时不显示已下载提示。界面显示的数据库列表和已存等级由服务器按队伍捕获后发送，客户端不自行查找数据库。

悬停只补充被截断的完整名称、原生物品信息、禁用原因或操作后果；已经在正文完整显示的材料名称与数量、需求行和底部状态行不再整行重复弹出相同内容。

## 遗忘个人等级

遗忘能力沿用服务端已有的个人遗忘（`ServerResearch.requestForget`，`ResearchWorld.forgetPersonal`）：只作用于本人在当前队伍的个人等级，从指定等级 k 起删除 k 及以上的后缀，结果为 `min(当前个人等级, k - 1)`，没有材料、能量或经验费用，不退还已付材料，已有的奖励领取资格、数据库中已下载的内容和队列中已付的进度都不改变。两种普通下载策略都有个人等级；特殊研究不使用个人等级，因此不显示遗忘按钮。个人等级为 0 或研究的个人来源被未完成的物品下载占用时按钮禁用并悬停说明；没有权限时（服务端 `forgetPermission`）同样禁用。

遗忘按钮位于详情底部，文字为“遗忘个人等级”。点击后底部切换为确认区：显示“遗忘 Lv.k 及以上”和减少、增加两个方形按钮（k 范围 1 到当前个人等级，默认遗忘全部），并列出本次遗忘的后果，之后才显示“确认遗忘”和“取消”。后果按服务器的有效等级算法在客户端预估，包括：个人等级与队伍等级的变化（队伍等级取所有成员个人等级的最大值，其他成员仍持有时不变）；队伍等级回退使其他研究的前置不再满足时，逐项列出回退的研究及等级；队列中因此失效的条目。点击确认时随请求携带界面显示的个人等级，服务器用它校验后执行，不一致按已过期拒绝。ESC 先取消确认区，再收起详情。

## 编辑模式

编辑模式由有权限等级 2 的执行者通过服务器命令开启，可为本人或指定在线玩家开启，界面与玩家模式相同，顶部提示条改为黄色。

编辑模式提供“一键遗忘”和“全部完成”调试按钮，范围为当前队伍的全部普通研究，包含隐藏研究和其他分页。全部完成把当前全体队员（含离线成员）的研究等级提高到定义最高级，并创建未领取奖励资格；一键遗忘清除这些队员的普通研究等级和旧队伍直属等级。两者均清除当前研究队列，保留已支付材料进度和奖励领取记录，特殊研究继续单独编辑数据库。服务端必须检查本次管理员编辑授权、当前队伍及所有相关源的占用状态，未通过前禁止修改任一研究；普通批量操作统一保存一次，材料恢复仍执行必要的持久化检查点。

编辑模式下点击研究方块的效果与玩家模式相同，只展开节点并打开右侧详情，不修改研究；区别是前置未完成的研究也可以点击打开。研究由详情底部的研究按钮执行：按钮仍为“开始研究”，点击后立即完成下一级，不进入队列，无视前置、互斥、权限、材料、研究时间与开始条件；已达最高等级时按钮禁用。特殊研究的按钮为“写入数据库”，点击后写入当前活动数据库并加 1 级，没有活动数据库、需要新增条目但容量已满或已达最高等级时按钮禁用，悬停说明原因；库内已有该研究时提升等级不额外占用容量格。

有效等级计算会把前置未满足的研究按阶段回退到 0，所以立即完成时缺少的前置研究必须同时补到所需等级，否则完成后的研究仍显示为未完成。完成结果与正常完成一致：提升完成时全体队员的个人等级，并为新完成的每一级创建奖励领取资格；队列中目标等级不高于新等级的条目移出。服务器收到请求后必须重新确认命令授权，再通过完成传播（`TeamResearchCompletion`）写入并保存；禁止在客户端修改等级。管理员设置等级（`requestAdminTeamLevel` / `requestAdminPlayerLevel`）不创建领取资格，不能直接用于编辑模式。

编辑模式右上角的布局按钮在自动布局和手动布局间切换。切换到手动布局时保留当前全部坐标，并显示长按研究以拖动的提示；只有手动布局允许长按研究方块约 0.3 秒进入拖动，自动布局下拖动只平移画布。按下后 0.3 秒内移动超过 3 像素仍按平移画布处理。拖动时研究跟随光标，松开时记录新坐标，不吸附网格，也不检测或拒绝重叠。切回自动布局必须清除该页的手动位置并立即按前置关系重新排列。模式和坐标变更保存在当前编辑界面，点击“全部导出”统一提交所有分页。连线随位置自动重算。

记录的坐标保存在客户端内存中，“全部导出”将所有分页的设置分别写入各自分页文件；写入失败时记录错误日志并在界面提示，禁止写入其他路径。详情的研究信息中额外显示研究 ID 和当前像素坐标。

编辑模式在画布上右键打开选择菜单：

- **添加分页**：填写分页 ID 与显示名称，创建一个自动布局的空页并切换到新页。分页 ID 使用小写字母、数字、下划线、点和短横线，不能与已有分页重名；显示名称保存在服务端分页文件中。
- **添加研究**：按名称或完整 ID 搜索并选择已由 Java/ZS 注册的研究，加入当前分页。一个研究只在一页展示，已在其他分页时移动到当前页；当前页已有的研究不重复加入。手动布局使用打开右键菜单时的画布位置，允许重叠；自动布局保持自动并按同页前置重新排列。
- **编辑研究**：右键研究节点时额外提供此项，打开界面内的多行 JSON 编辑窗口。下拉可选 `data` 基础文件或 Minecraft 当前支持的某个语言；选择语言后编辑该语言的字段覆盖文件。支持选择、剪贴板、撤销、滚动与光标移动。切换目标前须保存或取消现有修改。

新增分页和移动研究由服务端校验后立即保存。如果分页刚从自动布局改为手动布局，添加研究时一并保存原成员拖动前的自动坐标。拖动修改仍保存在当前界面内，点击“全部导出”才统一提交所有分页。文本编辑器选择 `data` 时将基础文件保存到服务端，选择某个语言时将本地化字段保存到当前客户端。解析或保存失败时，界面显示错误，原配置仍然有效。材料、时长、前置和奖励处理仍由 Java 或 ZS 注册。

## 研究内容、分页文件与同步

服务端提供研究注册定义、分页和基础展示。玩家进入单人存档或连接服务器后，服务端按其研究状态发送可见分页、节点名称、图标和布局所需数据；目录或可见范围变化后更新。打开某项研究的详情时才请求完整基础文本、材料、资源和奖励展示。服务端检查研究是否对该玩家可见，隐藏研究的 ID 也不会出现在可见研究的互斥说明里。游戏界面的翻页、平移和缩放仍按客户端保存的视角恢复。

管理员可通过 `/pe research reload` 重新读取服务端修改过的基础展示和分页文件，该命令要求权限等级 2。配置有误时保留当前目录并记录具体错误。界面内保存服务端配置后直接同步，无需另行执行命令。

服务端基础文件位于 `config/prototype_eng/research_content/data/<命名空间>/<研究路径>.json`，客户端本地化文件位于 `config/prototype_eng/research_content/<语言代码>/<命名空间>/<研究路径>.json`，例如 `zh_cn/pe_run_tests/research_station.json`。客户端用当前语言覆盖收到的文本字段；对象按字段覆盖，数组整体替换。缺少语言文件时直接使用服务端文本。服务端缺少基础文件时以研究 ID 为名称并记录警告。

基础文件支持 `title`（名称）、`summary`（简介）、`description`（说明字符串数组）、`icon`（图标对象）、`rewards`（奖励组文字对象）和 `visibility`（可见模式）。`rewards` 的键为完整奖励组 ID，每组可提供 `title` 与 `description` 字符串。语言文件可覆盖名称、简介、说明及指定奖励组的部分或全部文字；图标和可见模式由服务端决定。文字字段填写直接显示的文本。

`visibility` 可以覆盖 Java 或 ZS 注册时声明的可见模式。`always` 为默认值，研究本身不要求解锁条件；`after_prerequisites` 要求达到各前置研究在所有等级段中要求的最高等级；`after_completion` 要求该研究至少完成一级。三个模式都受前置研究的可见性约束，任一前置不可见时，依赖它的研究也不可见，包括跨分页依赖。可见性只限制总览展示，不改变研究的资格、进度和队列规则。设为 `after_completion` 的研究需要通过普通总览之外的入口完成第一级。普通总览隐藏没有可见研究的分页；编辑模式显示全部已注册研究及已配置空页，便于调整归属和布局。

服务端分页文件为 `data/<分页ID>.json`，与研究内容的命名空间目录并列。默认按研究命名空间分组，也可通过 `researches` 显式指定已注册的完整研究 ID，允许跨命名空间。研究加入显式分页后不再出现在默认命名空间页。空列表保留分页配置，普通玩家在有可见成员后才能看到它。`title` 可填写直接显示的名称，省略时从客户端读取 `gui.prototype_eng.research_page.<分页ID>` 本地化键。

```json
{
  "priority": 10,
  "layout": "manual",
  "title": "自定义研究页",
  "researches": ["pe_demo:basic_circuit", "pe_demo:data_storage"],
  "positions": {
    "pe_demo:basic_circuit": [0, 110],
    "pe_demo:data_storage": [100, 50]
  }
}
```

`priority` 为 32 位有符号整数，缺省为 0，数值越小越靠前，相同时按分页 ID 排序。`layout` 为 `auto` 或 `manual`，缺省为 `auto`；编辑模式通过布局按钮切换，只有 `manual` 允许拖动研究。`positions` 只在手动布局时生效，键为完整研究 ID，值 `[x, y]` 指定研究方块左上角在画布中的整数坐标。缺少坐标的研究排在已有坐标的最大 y 之后空两个行距的位置，每行最多 6 个。分页文件不存在时按同命名空间成员和自动布局处理。“全部导出”一次提交所有分页的布局模式与手动坐标，服务端在写入前校验完整分页集合和各页坐标，保留各页优先级、标题、成员与暂未注册成员；自动分页不保存手动坐标。所有分页各自写入原配置文件，任一文件保存失败时按原分页配置恢复已写入部分。

自动布局按同页前置关系计算列：没有同页前置的研究位于第 0 列，其余研究位于同页前置最大列加 1。同列研究优先放在其前置所在行，冲突时下移。没有任何同页前置关系、也不被同页研究依赖的研究，排在前置树下方空一行后，每行最多 6 个。跨页前置不参与列计算。列和行按列距 92、行距 40 换算为像素坐标，因此自动布局与手动布局共用同一种坐标。

## 图标解析注册

图标 JSON 的 `kind` 决定解析方式，内置三种：

| `kind` | 字段与解析结果 |
|---|---|
| `item` | `id` 为物品注册 ID，`meta` 可省略且默认为 0，解析为 `AEItemKey`。 |
| `fluid` | `id` 为 Forge 流体注册名称，例如 `water`，解析为 `AEFluidKey`。 |
| `icon` | `id` 为完整 AE 图标 ID，使用 `Icon.byId` 解析为 AE `Icon`。 |

使用方在客户端初始化、首次显示研究内容之前调用 `ResearchIcons.register(kind, parser)` 注册新的 `kind`。解析器接收服务器发送的图标 JSON 对象，返回可绘制的 `ResearchIcon`，可以使用自定义字段。客户端记录未注册的 `kind` 或无效图标，并标明研究 ID。

## 与现有实现的关系

研究总览通过专用容器同步已完成等级、队列、当前研究进度和材料、奖励领取状态、队伍数据库和数据库模式候选。开始研究、手动投料、奖励、下载、遗忘和编辑均由服务端重新检查当前权限与状态。关闭详情或改选研究时，当前容器不再保留原详情数据。

## 示例 mod

`run` 测试包新增 HTML 的十四项 `pe_demo` 与六项 `pe_showcase` 研究，加上原 Java 五项共三页二十五项；标准 CT 测试入口另注册原 ZS 五项，合计三页三十项。`pe_demo` 使用与 HTML 相同的手动作者坐标；`pe_showcase` 自动布局，覆盖 32 材料、六资源、流体、长文本、十二物品奖励、多组选择、手动多等级和跨阶级等场景。二阶研究站与二阶数据库用于真实推进；完整材料、网络供给和游戏复验步骤见 [研究示例](../run/scripts/README-research-overview.md)。HTML 仅是布局预览，不替代实际注册、世界状态和游戏验证。
