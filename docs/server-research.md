# 服务器研究与世界存档

服务器已接入手动研究的世界所有者、同步存档、FTB 成员核对、玩家登录退出和既有调度边界。Java 使用方可调用 `ServerResearch.startManual` 开始 tier 0 研究，或 `takeoverManual` 接管已有会话；输入必须是真实在线服务端玩家。库不注册研究内容、正式机器或玩法数值。

## 所有者与生命周期

`ResearchWorld` 在创建线程持有全部玩家研究来源、队伍直属研究、黑名单、队列和手动会话。`ResearchWorldSnapshot` 是不可变快照，`ResearchWorldNbt` 复用现有玩家、队伍、队列和手动会话 codec，严格校验身份、等级、队头、时间及恢复所需玩家引用。

主类把 FML 生命周期委托给 `CommonProxy`。`serverStarting` 在主世界加载后建立准确的 server/overworld 会话；`serverStopping` 保存并关闭；`serverStopped` 在调度器关闭后提供研究关闭重试，再关闭网络和身份登记。主世界 Save 同步检查点，Unload 提供关闭兜底；其他维度不建立第二份研究存档。

研究 tick 由 `ServerTaskSchedulers` 的既有 END 流程通过 `runAtBoundary` 执行，普通 worker 已退出后再操作研究与背包。等待中的研究回调合并为一个，避免调度暂停后积压多次投料。未初始化或关闭中的会话正常跳过。时间取持久研究时间与主世界时间的单调推进，世界时间存盘落后于研究检查点时也不倒退。

## 同步存档与失败恢复

`ResearchStateFile` 独占主世界 `data/prototype_eng_research.dat`，不注册进 MapStorage。沿用 PN 的压缩 `{data: …}`、同目录临时文件、文件描述符 sync、原子替换和最终 force；不支持原子替换就失败，损坏或不可读存档不当作空世界。

世界检查点失败保留准确快照。下一次业务开始前先重写该快照，再恢复各手动执行器的私有检查点，之后才允许改变时间、成员和队列。写入前后校验世界仍对应同一快照；外部回调和 IO 异常保留原原因，不转为正常业务结果。关闭失败保留 closing 会话与数据，后续 Save/Unload/Stopped 可重试。

手动研究入队后若尚未安装会话，失败可移除准确的新队列项；若已经安装会话或待保存意图，则保留队列与会话，避免保存失败后单方面删队头。玩家回执与世界记录的详细顺序见[手动研究](manual-research.md)；两个文件之间没有文件系统原子提交，恢复依赖已有回执证据。

## 成员变化与无效研究

捕获种子覆盖在线玩家和所有活跃队列/会话涉及的玩家，并递归查询成员，包含离线玩家。FTB owner/moderator 与服务器 OP 由服务端读取；每个成员的反向队伍归属必须一致，操作前后重验当前会话、成员和在线玩家对象。Universe 不可用时暂停，不当作队伍解散。

登录只登记玩家，不自动恢复手动研究；退出暂停其所有 ACTIVE 会话，包括非队头。世界重载将 ACTIVE 转为等待接管，保留其他恢复状态。恢复后的手动执行器与后加入的成员共享同一个全局玩家来源表。

已有队列只核对结构资格，不重新调用开始条件。研究失效或队伍消失时，先处理手动会话持有的扣料/完成义务，再 prune 队列：未消费且有证据的准备可取消；已提交回执先结算；已付清的完成按冻结成员传播；未知回执或原玩家离线保留待恢复状态。`RESEARCH_INVALIDATED` 保留取消原因。个人来源和奖励证据不会因换队或解散被删除。

## 范围与验证

已接平台入口的是 tier 0 的开始、接管及自动推进。正 tier 的设备选择与研究站材料/计算提交、普通配方研究/计算消费者、领取 packet/UI 及存档事务绑定、下载仍未完成。`ResearchWorld` 可供外部服务器宿主使用，但其可调用 API 不等于上述玩法流程已接通。

本阶段新增 50 项逻辑测试：世界 owner/成员/失败重试/恢复，结构资格，手动无效取消，以及严格世界 codec 与临时目录真实文件 IO。完整构建通过 741 项测试、104 suites，无失败/错误/跳过。本机 IDEA MCP 对 16 个本阶段 Java 与生成 Tags 共 17 文件逐个 `errorsOnly:false`，零错误/警告/弱警告；MCP 项目构建成功。证据：`build/reports/idea/server-research-final.json`。

没有启动 Minecraft、Bootstrap 或 FML。真实游戏中的 FTB 事件顺序和背包操作尚无实机验收；这不由纯 JVM 文件测试替代。
