# PM 结构工具

## 2026-11-23 施工动画与全服预算

点开始后，服务端根据材料选择、结构段数、空间规则和 AE 设置预检。需要自动 AE 合成时先打开 AE 原生确认页。通过预检后关闭构建器界面并开始动画。打开背包、移动构建器或改变绑定时，施工继续；使用原构建器可以暂停和恢复。

搭建先显示施工格并集的白色轮廓，保留凸棱、凹棱和孔洞轮廓，合并连续直线。白线时长随实际施工格数按对数增加，限定在 6 至 28 tick。服务端从较低处开始，沿面相邻的施工方块分组，每组目标 500 格。每个任务最多 32 组。剩余格数超过可分配的容量时提高每组容量。切分出的余块使组数超出上限时，优先并入相邻且满足支撑顺序的组，合并后最多比当前组容量多三分之一。相互分离的部分无法在上限内分开时共用动画时间。

同一组可跨区块、跨 tick 放置。整组完成、邻居通知处理完且原版区块更新发出后，白壳在 8 tick 内整片淡去，此时后续组可继续施工。发起者在屏幕底部看到还缺、错误和未加载的格数。施工结束提示保留 60 个客户端 tick（正常速度下 3 秒），成功时文字变绿。

搭建队列处理完全部目标后，发起者在聊天框收到总用时，单位为秒，保留两位小数。计时从服务端接受搭建请求开始，包含预检、开场动画、等待及暂停。配置允许跳过目标时，消息说明仍有未完成的位置。取消搭建和拆卸不发送这条消息。

同一组内，可独立放置的静态方块按柱从高到低写入，动态方块和受重力方块使用原版流程，从低到高安装。所有固体目标均已匹配或完成放置，并且邻居通知已处理时，才开始放置流体。正在等待材料或重试的固体会阻止注水，允许跳过固体并留下缺口时，本次跳过流体并向发起者提示。流体与同组固体独立褪色。

搭建和拆卸按完整结构坐标使用同一套分组，已有方块、空位和缺料不改变分组边界。拆卸先清理流体，再拆固体；两阶段都逆序处理搭建分组，同组从高处往下拆。当前组开始拆除时，同阶段的下一组开始变白，轮到下一组时只等待尚未完成的动画。需要重试的目标留在队首，避免拆除后续组。最后在 20 tick 内使白线淡出。

在原版 `RenderWorldLastEvent` 绘制，使用深度测试和填充多边形偏移。发起者和旁观者都按到完整结构包围盒最近点的三维距离裁剪。超过 32 格时不构建、上传或绘制施工网格，发起者的施工状态提示也会隐藏。范围内按 `16 × 16 × 8` 的网格切片做视锥裁剪。同一切片可以包含多个施工组，白线仍按整个方块并集生成一次。开场白线可见期间，剩余的每帧构建预算可提前准备可见的固体白壳。几何或边界变化时才更新相应顶点范围。

同一任务的区段共享顶点缓冲。满白区段不启用混合，写入深度以挡住后方白面；褪色区段保留各自的透明度，不写深度。相同透明度的可见区段合并提交顶点范围；同时出现不同透明度时，复用缓存坐标并在批次中填入各区段的透明度。白线也按同一任务的可见范围合并。关闭 VBO 时复用客户端顶点缓冲，裁剪和褪色规则相同。

服务端按完整结构的 32 格范围和原版区块观看关系发送几何。首次发送完整范围和开工参数。同组跨区块时只向每位玩家发送一次变白或褪色时间。玩家走出范围后停止接收特效，返回时仅补发缺少的状态、新观看的区段及有坐标变化的快照。原版区块卸载事件直接清理对应几何。实际方块沿原版同步。发起者的提示数据只在数值或暂停状态变化时发送，结束消息对每位接收者只发一次。

区段位置使用稀疏位置表或密集位图。组号根据数据选择单个编号、连续同组编码或每格 5 位，空格不占组号空间。单包最多 16 KiB，全服每 tick 最多发送 64 KiB 和 128 个特效包。特效发送独立于放置预算。施工特效的编码已更新，联机时客户端与服务端须使用同一版模组。

所有维度的搭建和拆卸队列共用 `config/prototype_eng/builder.cfg` 的 `construction.tickBudgetMillis`，默认每 tick 10 ms。首次加载时删除旧的 `workIntervalTicks` 和 `blocksPerBatch`。管理员执行 `/pe builder budget 20` 可将预算设为 20 ms 并写回配置文件；直接编辑文件后可执行 `/pe builder reload`。预算必须为正整数，正在执行的队列从下一 tick 使用新值。

施工在服务端 tick 的 `START` 阶段执行，原版在之后处理世界与玩家区块更新，再记录整刻耗时。首轮在可执行队列间均分并轮换起点，提前完成或等待的队列把余量留给仍可推进的队列。每次方块操作返回后检查份额，到达截止时间后停止开始下一格。已经开始的原版操作、同步光照、Forge 事件和材料回调执行完毕。结构展开和预检可以跨 tick。

普通静态方块使用已加载区块的 `Chunk.setBlockState`，由原版维护高度和天空光。方块实体、流体和其他动态方块沿用常规流程。服务端保留 Forge 可取消事件、权限检查、快照恢复和材料退款。静态快路径延后的光照和通知在当刻放置结束后批量处理，耗时不预留或抵扣后续份额。光照按世界、区块、坐标和光照类型去重，按写入前和最终状态的属性差异处理，已回滚到原状的坐标无需再次检查。邻居通知只合并同一来源位置，保留不同来源的邻居及观察者回调。

### 游戏内复验

使用同一份存档和相同的施工预算，分别搭建纯静态结构、[星穹观测站](../run/README.md#星穹观测站)和两个同时开工的结构。可以用 `/pe builder budget 20` 设置 20 ms 对照预算。每次在相同位置和视角开工，记录实际放置格数，按施工操作累计毫秒计算吞吐。`/forge tps` 的 `Overall` 行显示最近 100 刻的平均耗时，按维度的行不单独计入这份全服队列耗时；总耗时低于 50 ms 时 TPS 仍会显示 20。服务器原版性能分析的 `root.peConstruction` 下分别记录 `operations`、`lighting`、`notifications` 和 `effects`。客户端用 F3 查看帧时 P95/P99、绘制提交数和上传字节数，性能分析的 `peConstruction` 下用 `meshUpload` 和 `submit` 区分网格处理与绘制提交。

复验跨区块的同组白壳是否一起褪色，下一组是否能在前一组褪色时继续施工。检查下层先显出原材质、斜视玻璃时无闪纹、跨区块的方块光和天空光、先拆流体和最后注水、缺料后补充、Forge 事件取消、施工中打开背包、旁观者晚加入和离开 32 格范围后返回。分别用开启和关闭 VBO 的客户端复验。

## 2026-11-14 构建器独立 AE 绑定与升级

将构建器放入无线接入点的绑定槽，取出后即可使用其自身保存的网络绑定。网络绑定与原有结构绑定分别保存；取料、退款、自动合成、物品回收和流体回收全部使用发起任务的构建器。背包中其他无线终端不参与选择。

构建器闲置时，点击主界面右上方的升级按钮进入独立配置页。页面使用 AE 原生背景、背包槽、升级侧栏与返回按钮。一个升级槽允许安装一张量子桥卡；安装量子桥卡后显示一个纠缠奇点槽。奇点必须与网络量子桥配对，连接优先使用同网无线接入点，量子桥支持跨距离、跨维度访问。已有无线绑定能够解析时，量子桥必须属于同一个网络。拆下量子桥卡后，已装入的奇点仍可取出。

构建器使用普通 AE 物品基类，不提供电量、充电能力或能量卡支持。取料、回收与退款通过玩家 PlayerSource 直接调用绑定网络的存储接口。无线接入点及量子桥保留 AE 网络自身的供电和权限要求。关闭使用AE后，原本的背包供料与回收继续可用。

工具提示直接复用 AE 的 GuiText.Linked、GuiText.Unlinked 与 Tooltips.colored，分别以绿色显示已链接、红色显示未链接。提示表示工具保存的 AE 绑定状态，服务端实际操作时检查网络是否可用。

任务只创建一个连接会话，同一 tick 复用连接选择结果。升级 NBT 列表变更后才重新读取量子桥卡状态；升级槽使用 AE 的动态物品库存，以支持客户端物品同步。延迟掉落继续持有原会话，原工具离开任务槽位时只交回玩家，不查找其他终端。构建界面的状态同步排除升级卡、奇点与网络绑定数据。

实机复验入口：分别为两把构建器绑定不同网络，并携带连到第三个网络的无线终端，确认取料及物品、流体回收仍进入各自绑定的网络；复验副手使用、网络断开、断电时的回收、升级卡及奇点装卸、跨维度量子连接、保存重开，以及缺料的 AE 合成确认与返回。实际游戏行为等待用户复验。

## 2026-11-14 挖掘回收与使用AE

开关名称改为“使用AE”。搭建仍优先使用背包材料，缺少部分从构建器绑定的网络取出；挖掘物品和收集的流体优先存入该网络。存入使用网络存储接口和玩家 `PlayerSource`，不要求磁铁卡，也不读取磁铁卡过滤、吸取模式或潜行状态。绑定、范围、权限和网络容量沿AE原接口处理。未接通或只存入一部分时，只把剩余量交回玩家。

拆解先处理全部目标中的世界流体，再挖掘普通方块。尚未完成的流体会重试，普通目标保持等待；已成功抽取的目标不会因邻居补流再次收集。关闭完整空间需求后的建造清障也先回收流体，随后为相应目标支付建材并放置方块。严格空间模式中的“忽略世界流体”仍按原规则直接替换。

非AE回收及AE未接收的物品先进入玩家背包，装不下的物品以零初速度生成在玩家脚下。流体先尝试直接库存及一层可写背包容器，剩余量包装为AE资源包，再按背包、脚下的顺序交付。回收的AE资源包在存入AE时使用包内资源类型和数量，不把流体包当成普通物品存储。

方块继续使用原采掘等级、精准采集、时运、BreakEvent及原生harvestBlock。只捕获当前挖掘调用产生的物品，不扫描附近已有实体，不处理其他事件已经取消的生成。资源仓、运算仓和ME仓在拆除时记住交付函数，预留结算后才释放的库存也按同一路径交付；玩家已离线或离开该世界时，延迟物品落在其挖掘时的脚下位置。

实机复验：开启使用AE后拆除带流体的结构，观察液体全部处理后才出现方块破坏；分别测试可用、断网、无电、存储满和部分可接收的ME网络。切换磁铁卡黑白名单不应影响构建器回收。再关闭使用AE，分别留空和填满背包，确认物品与余量资源包进入背包或玩家脚下。保护事件取消、模组方块额外掉落及仓室延迟库存也需实机验证。编译和单元测试不代替这些World行为。

## 2026-11-13 构建器预检、ME与外部结构

构建器保持原384×228界面及384×256底图，右侧进度条上方为两列三行六个开关：完整材料需求/等待材料补充、完整空间需求/忽略世界流体、使用AE/自动AE合成。直接复用结构选择工具20×13原开关及底图21×14固定框/阴影；文字宽54正常分行，提示名称/状态/说明分行并限宽160。材料树高度130、y138..140收口，开关区y143..202。设置保存于工具NBT且仅闲置可改；前置关系由客户端和服务器共同检查，关闭前置选项时清除从属开关的开启状态。

| 开关 | 作用及前置 |
|---|---|
| 完整材料需求 | 开启时必须备齐待建材料才开工；关闭后允许部分搭建。 |
| 等待材料补充 | 仅完整材料需求关闭时可开。缺料时停在当前方块，补齐后自动继续；关闭则跳过该方块并继续下一个。 |
| 完整空间需求 | 开启时待建位置必须全部为空气；关闭则按构建器采掘能力自动挖掘占位方块后放置。已放对的方块保留。 |
| 忽略世界流体 | 仅完整空间需求开启时可开。将已有世界流体视为空气，允许在这些位置搭建；不忽略结构需要的流体。 |
| 使用AE | 搭建缺料时从AE取料，挖掘所得物品及流体优先存入AE；未接收部分交回玩家。 |
| 自动AE合成 | 仅使用AE开启时可开。为可合成的缺料打开AE确认页，确认后由CPU处理。 |

预检先排除已放对的blockstate，检查加载、高度、权限及空间策略。完整空间需求只认可空气；开启忽略世界流体后，世界流体也可占用。关闭完整空间需求时，允许清理可采掘的障碍，无法处理的位置报告并跳过。严格按当前全局/单格选择和分段次数统计待建资源；物品每格一个、流体每格1000mB，半桶不能支付整格。初始缺料准确报告。关闭完整材料需求且关闭等待时按预算筛选能完整支付的位置；开启等待则保留完整目标并在缺料位置停止，补料后继续。开工后材料消失同样按等待/跳过处理，完整材料模式则等待。世界流体先回收；普通障碍在材料托管成功后才采掘，沿原工具能力、掉落和Forge事件；放置失败退材料，已挖位置保持为空位，不恢复已产掉落的旧方块。

ME使用构建器自己的绑定和玩家ActionSource直接提取，按AE规则处理距离、网络供电和权限。背包材料可以来自直接库存及一层可提取ItemHandler，流体容器要求可写handler，预检与实际扣料使用同一入口。退款尝试回原ME；无法接回时将实际未接回部分交给玩家为原生资源包。

合成只提交当前规划的缺料，不尝试替代项；可合成部分进入AE原生确认页，不可合成的部分仍在缺料报告中。用户确认后由AE CPU处理，确认页完成/取消后回玩家背包。部分搭建且开启等待时，当前任务会等待材料并继续取料；完整材料模式未开工或已跳过缺料时，合成完成后再次开工。AE临时样板用工具key作为批量分组占位输出，由AE内部处理，不复制或返还构建器。部分搭建时是否等待缺料由“等待材料补充”决定。

投影每tick最多检查2048格，不受当前显示片层限制；实际blockstate等于当前规划目标时隐藏该格，整轮检查全部匹配后撤销投影。未知、未加载或任何片层仍缺块都会保留；空规划立即撤销。30秒到期和Shift+滚轮仍保持。这个观察只判断规划方块是否覆盖，不代替机器结构匹配、NBT或其他运行条件，也不自动切到下一层。

流体展示统一从目标state识别IFluidBlock/Forge注册流体及原版水、岩浆；直接包装AEFluidKey，每格1000mB。预览射线对流体格使用格子范围，其他块保留原碰撞射线及getPickBlock；图标、材料树/网格数量、完整结构样板输入均走同一流体身份。样板始终导入全部规划层，例如3格水为3000mB，而不是三个水桶物品或3mB。

施工使用[全服共享预算](#2026-11-23-施工动画与全服预算)。施工开始时读取构建器的材料选择、采掘工具和 AE 绑定，服务端任务保存施工目标、状态和进度。打开界面、移动构建器或重新绑定时，施工继续使用启动时的目标和设置。只有原构建器能打开任务进度并用按钮暂停或恢复。使用其他构建器发起任务时提示当前已有施工。

## 外部主方块注册

客户端和服务端在 `postInit` 解析结构后发布 `StructureConstructionRegistrationEvent`。可在此将外部主方块的准确 `IBlockState` 关联到已注册结构。主方块占据原点，搭建和拆卸均保留它。默认按当前结构定义的原朝向搭建和预览；方块即使带有 `facing` 也不会自动改变结构朝向，方向工具不接管该方块。

显式传入 `StructureAnchorRotation` 后，搭建和拆卸读取主方块的实际朝向。方向工具和预览使用同一套可选姿态：

- `fourWay(facing)` 使用水平正面，顶部固定朝上。
- `sixWay(facing)` 支持六个正面，每个正面使用 AE 的标准顶部，不改变绕正面的滚转。
- `twentyFourWay(front, top, callback)` 预测两个互相垂直的方向属性，支持每个正面的四个顶部方向。可额外传入读取回调，把实际姿态读自方块实体。

```java
@SubscribeEvent
public static void construction(StructureConstructionRegistrationEvent event) {
    var rotation = StructureAnchorRotation.fourWay(ReactorBlock.FACING);
    event.registry().register(MyBlocks.REACTOR.getDefaultState(),
        new ResourceLocation("addon", "reactor"), () -> "addon.structure.reactor",
        rotation, (state, tile) -> tile instanceof ReactorTile reactor && reactor.isFormed());
}
```

预设保留其他属性，注册时自动关联同一主方块的朝向变体。每个其他属性组合需分别注册，例如主方块本身有成型属性时，应分别注册成型前后的状态。重复状态和未知结构 ID 会报错。构建器和 HEI 可在原点点选主方块；同一次注册的旋转变体共用一个 HEI 条目，样板输出仍是主方块物品。对准外部主方块打开独立投影时，先使用主方块当前朝向。已注册旋转的投影可主动按 `R` 跟随玩家方向，或按 `[`、`]` 在支持的姿态内调整。

可用 `withCallback((state, tile, world, pos, player, orientation) -> ...)` 替换预设的服务端写入。对由方块实体或其他属性保存朝向的主方块，还可给 `fourWay`、`sixWay`、`twentyFourWay` 传入读取、预测状态和实际旋转三个回调。读取和预测必须只读；读取在物品预览或缺失方块实体时接收 `null`，仍须返回合适的朝向。预测必须返回同一个方块的目标状态；纯方块实体存储可原样返回状态。实际旋转回调负责写入和同步，只有旋转成功才返回 `true`。只传入 `Function<IBlockState, BlockOrientation>` 的注册可读取当下朝向供搭建使用，也不会启用方向工具或预览旋转。

四向和六向的属性预设使用原版状态更新，方向属性由主方块保存和同步。原版 1.12 的方块 metadata 只有四位，二十四向必须通过旋转回调写入并同步完整姿态。使用 AE 原生方块实体且支持全朝向时，`twentyFourWay(block)` 复用 AE 的方向策略、方块实体存储和客户端同步。外部结构需要限制已成型时转向的，可以在自定义回调中拒绝。

成型检查可接收 `(state, tile)`，也可接收 `(state, tile, world, position)`。服务端启动施工时传入当前状态，方块实体缺失时传入 `null`。返回 `true` 时拆卸，否则搭建。成型检查应只读已加载区块。执行异常会记录日志并取消本次启动。

CraftTweaker 脚本使用 `registerBlock` 关联所有合法状态，或用 `register` 注册一个准确状态，这两个入口都保持固定朝向。用 `registerFourWay` 或 `registerSixWay` 启用状态预设，最后一个参数为方向属性名。`registerTwentyFourWay` 使用支持完整朝向的 AE 方块实体预设，例如元件工作台。

```zenscript
import mods.prototype_eng.structure.Construction;
Construction.registerBlock("addon:fixed_anchor", "addon:fixed_shape", "addon.structure.fixed_shape");
// anchor 是已经取得的 crafttweaker.block.IBlockState。
Construction.registerFourWay(anchor, "addon:reactor", "addon.structure.reactor", "facing");
// aeAnchor 是支持完整方向的 AE 方块状态。
Construction.registerTwentyFourWay(aeAnchor, "addon:workbench", "addon.structure.workbench");
```
