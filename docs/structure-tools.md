## 2026-11-13 构建器预检、ME与外部结构

构建器保持原384×228界面及384×256底图尺寸，仅清除按钮边缘露出的29像素旧坐标图标；右侧原面板内部、进度条上方新增两行四按钮（y154/177）。材料树显示区域缩至144像素，裁剪、鼠标命中、滚轮和拖动边界同步缩短，避免遮住按钮。按钮使用结构导出按钮的边框、阴影及默认/悬停/按下三态，中心取纯背景列，不把导出图标拉伸到文字后面。设置保存于工具NBT，仅闲置时可改，旧工具默认要求齐料和所有位置可放、禁止覆盖液体、仅用背包。

| 按钮 | 开启或模式含义 |
|---|---|
| 材料齐了才开工 | 开启：有缺料或无法确定的规划目标就不开工；关闭：报告缺料，仅加入能付足材料的完整位置，本次跳过缺料位置。 |
| ME取料/合成 | 循环关闭、取料、取料+合成。先用背包；不足部分通过AE可用无线终端取料。最后一档还会为可合成的缺料打开AE原生批量合成确认页。 |
| 全部能放才开工 | 开启：有被挡、未加载、超世界高度或无权限位置就不开工；关闭：报告并跳过这些位置。已经放对的目标不算障碍。 |
| 允许覆盖液体 | 开启：已有水、岩浆及模组液体可直接被规划方块覆盖；关闭：也算障碍。覆盖不回收旧液体，不会跳过规划中的流体。 |

预检先排除已放对的blockstate和不可放位置，按当前全局/单格选择及分段次数统计实际待建资源。普通方块每格一个实际pick物品，流体每格1000mB；库存副本及ME SIMULATE只建立本次预算，不在开工时扣整批材料。准确缺少的名称与数量发到聊天，半桶不能支付一个流体格。同种资源预算只分配一次，普通方块先于流体/重力方块；关闭齐料开关时缺料位置不留在重试队列。途中资源消失时也报告并跳过（齐料开关关闭时）。库存与ME是逐格扣料；权限、放置失败/取消和异常会退款，覆盖液体失败恢复原位置。外部事件保护仍可在实际操作时否决，并不能由预检保证所有事件一定放行。

ME沿AE2S 1.1.1的WirelessTerminalApi可用终端查询、玩家ActionSource及带能耗的StorageHelper提取，继承绑定、距离、电量、网络和权限检查。背包材料可以来自直接库存及一层可提取ItemHandler，流体容器要求可写handler，预检与实际扣料使用同一入口。退款尝试回原ME；无法接回时将实际未接回部分交给玩家为原生资源包。

合成只提交当前规划的缺料，不尝试替代项；可合成部分进入AE原生确认页，不可合成的部分仍在缺料报告中。用户确认后由AE CPU处理。确认页完成/取消后回玩家背包；材料合成完成后重新打开构建器并再次开工。AE临时样板用工具key作为批量分组占位输出，由AE内部处理，不复制或返还构建器。部分搭建允许时已准入的目标继续处理，缺料仍在这次跳过。

投影每tick最多检查2048格，不受当前显示片层限制；实际blockstate等于当前规划目标时隐藏该格，整轮检查全部匹配后撤销投影。未知、未加载或任何片层仍缺块都会保留；空规划立即撤销。30秒到期和Shift+滚轮仍保持。这个观察只判断规划方块是否覆盖，不代替机器结构匹配、NBT或其他运行条件，也不自动切到下一层。

流体展示统一从目标state识别IFluidBlock/Forge注册流体及原版水、岩浆；直接包装AEFluidKey，每格1000mB。预览射线对流体格使用格子范围，其他块保留原碰撞射线及getPickBlock；图标、材料树/网格数量、完整结构样板输入均走同一流体身份。样板始终导入全部规划层，例如3格水为3000mB，而不是三个水桶物品或3mB。

配置文件为`config/prototype_eng/builder.cfg`，启动加载；配置生效后建造和拆卸共用限额：

```properties
construction {
    I:workIntervalTicks=1
    I:blocksPerBatch=8
}
```

`workIntervalTicks`范围1–1200，20tick约一秒；`blocksPerBatch`范围1–4096，已完成格不占本批尝试额度。默认保持每tick八个未完成位置；例如间隔5、批量4，理想情况下每秒最多16个位置，事件拒绝与暂时缺料仍会影响实际速度。

普通外部方块不用实现MachineControllerHost或创建本库TE，只需把准确anchor state关联到已注册结构。两侧postInit结构解析后发StructureConstructionRegistrationEvent，随后冻结并检查结构ID；重复state和不存在的结构会报错。原点由外部方块占据、不会被搭建；外部绑定仅提供建造，不冒充外部模组的成型/拆卸状态。结构必须已有完整方块展示，嵌套和动态段数仍用本库现有展开。

Java扩展在Forge事件订阅者中注册（类型按实际import）：

```java
@SubscribeEvent
public static void construction(StructureConstructionRegistrationEvent event) {
    event.registry().register(MyBlocks.ANCHOR.getDefaultState(),
        new ResourceLocation("addon", "reactor"), () -> "addon.structure.reactor");
}
```

默认朝向读取名为`facing`的EnumFacing属性，无该属性为NORTH_UP；垂直面默认朝北。四参数register允许传入Function<IBlockState, BlockOrientation>适配外部完整朝向。CT脚本沿既有runtime声明阶段排队，声明该结构后注册锚点；`registerBlock`关联该方块全部合法state，`register`接收CT准确IBlockState：

```zenscript
import mods.prototype_eng.structure.Construction;
Construction.registerBlock("addon:reactor_controller", "addon:reactor", "addon.structure.reactor");
```

## 2026-11-11 视角放置与九宫格转向

放置时仍按原六面/活塞规则选正面，再将玩家视角的“上”投影到正面平面，选择最接近的轴向作为机器顶部，得到完整spin。朝上、朝下放置随水平视角变化，斜视水平正面也能决定相应旋转；投影退化时使用视角水平朝向作确定回退。放置状态的完整方向沿现有state→tile构造/同步链传入，24向保存/同步及模型合同保持。

## 2026-11-11 工具融合与拆卸流体

在任意两个合成格放入构造器和一个工具，工具会被永久消耗；再次融合覆盖旧档案，不返还旧工具或新工具的合成容器。接受Forge声明工具类别的工具、AE扳手及普通耐久工具（普通护甲不算工具），不限原版镐斧铲。完整工具数据/附魔只保留当前一份，不积累历次工具；保留构造器绑定/材料选择，任务状态和进度复位。双语tooltip说明这些规则。

**档案只用于结构拆卸。** 构造器自身不增加工具类别、等级、挖掘速度、顶层附魔或扳手交互。拆卸按准确方块状态和工具等级/类别预验，工具快照交给原生`harvestBlock`处理精准采集、时运等掉落与相应经验；即使构造器在副手/其它槽位，也不借主手附魔。不调用工具主动交互、不消耗档案耐久；未融合保持3级拆卸基线，建造清障不使用档案。

AE的`InteractionUtil.isWrench`查询`getHarvestLevel(stack,"wrench",...)>=0`。本轮中间实现曾把默认3级暴露给全部类别，导致构造器被AE右键事件先识别为扳手；现已撤去物品的所有挖掘接口覆盖，不改AE钩子或事件优先级。构造器原右键绑定/打开、潜行绑定并打开保持。Java类变更需要完整重启，F3+T不更新类。

流体先过权限/BreakEvent，再使用Forge世界handler实际抽取。直接库存及一层可修改背包库存中的Forge流体容器优先填充，支持堆叠空桶、同种流体的剩余容量；结果容器不足空间时正常给出/掉落。只有装不下的余量掉落`GenericResourcePackageItem`，保留流体NBT和数量。不可抽取的流水只移除，不制造1000mB；无法识别handler的液体保留待处理。创造模式不产资源；源抽取成功即完成该目标，邻居补水不会令任务反复收集同一位置。
