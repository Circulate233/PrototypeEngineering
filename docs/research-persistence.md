# 研究增量存档

2026-11-18 按用户要求将研究存档改为按来源分片、只写变化记录。实现使用 JDK 文件接口、GZIP、SHA-256 和项目已有 NBT，不引入外部库；世界仍由服务端单一 `ResearchWorld` 所有者协调，不增加异步并发 writer。

## 保存时机

普通研究站的时间、网络资源累计以及同 tick 的材料提交先标记研究状态变更，不再每次推进都同步重写研究文件。主世界 `WorldEvent.Save` 调用 `ResearchWorld.saveChanged`，没有变更和失败待重试快照时不调用磁盘 writer。研究站库存与 FE 沿原机器/区块保存节奏落盘；非正常退出可能回到最近世界保存，研究文件与原生区块文件不是一个跨文件系统原子事务。

手动研究没有付款且没有完成的纯时间推进也只标记变更。`ManualResearch.Checkpoint.progressed` 默认调用原同步 `persist`，保持独立使用者的原有行为；世界适配器覆盖此方法来延后普通进度。普通检查点和物品支付/交付检查点不能只根据最终会话是否 ACTIVE 来推断：付款回执清理后同样可能回到 ACTIVE。

背包扣料、奖励交付、下载及研究盘导入的准备、提交、确认、清理继续保留既有同步检查点与物品证据。入队、管理操作和显式 `checkpoint` 保持原保存契约；必要检查点也会一并保存此前累积的普通进度。关闭/卸载仍保存最终状态，失败保留原会话供后续重试。普通保存期间所有者尚忙时先登记请求，在本次业务结算后处理。

单机房主的玩家屏障通过原生 `PlayerList.writePlayerData(player)` 仅保存对应玩家，沿原生覆盖方法刷新 hostPlayerData，然后核验 playerdata 与 level.dat 中的物品证据；不再为了一个玩家的付款调用 `saveAllPlayerData`。通过现有 Access Transformer 公开父类和单机覆盖方法，不使用反射或新增库。

## 文件划分

主世界的 `data/prototype_eng_research/` 保存：

- `players/<UUID>.dat`：一位玩家的个人等级与完整奖励领取链，包括 children 和交付片段。
- `teams/<SHA-256>.dat`：一个队伍的成员、黑名单、队伍等级、队列、目标进度和手动会话；文件名由 UTF-8 队伍 ID 计算，内容保留原 ID。
- `downloads/<UUID>.dat`、`receipts/<UUID>.dat`、`imports/<UUID>.dat`：各笔下载、下载回执与研究盘导入义务，互不混写。
- `meta.dat`：持久时间、提交身份与各类分片的有序身份/校验索引，不包含全部玩家的研究正文。
- `pending.dat`：仅在一笔提交或失败恢复期间存在，包含本次变化分片的完整目标字节、删除清单和原/目标提交身份。

写入时对编码后的各分片与持久缓存比较；未变化的分片不压缩、不替换，其字节和修改时间保持不变。变化的一位玩家不会导致其他玩家的等级、奖励或操作正文重写。变化粒度是玩家、队伍或单笔操作记录；GZIP 文件不做原地字节补丁。当前仍会捕获并编码业务世界快照以确定变化，不能把磁盘增量宣称为全部 CPU 工作也已经增量。

## 跨分片提交与恢复

先将本次变化发布为完整的 `pending.dat`，再替换变化的分片，最后发布新 `meta.dat`，之后删除不再引用的分片并清理 pending。单文件都使用同目录临时文件、批量字节写、文件描述符同步、原子替换及目标 force；不支持原子替换时明确失败。付款涉及多个玩家、队伍与操作时仍属于同一笔 pending，不能分开确认。

启动和下一次写入前先处理未完成 pending。当前 meta 必须等于 pending 的原提交或目标提交；已提交但尚未清理也是合法恢复状态。恢复按确切目标字节重放，检查所有被引用分片的校验和与身份后才发布世界。提交身份冲突、缺失分片、损坏文件或不可读路径均报错，不能把离线玩家或领取证据当作空数据。目录里没有被索引引用的文件不自动加入世界。

`ResearchWorld` 只有在 writer 正常返回后才释放准确 pending 快照；失败不得先推进其他研究。存储完成恢复前也不会开始另一笔不同的磁盘提交。这些规则覆盖串行所有者下的进程中止和 IO 失败恢复；JDK 的文件 force 与原子移动不构成已验证的任意掉电、磁盘控制器缓存或目录元数据回退保证。

## 旧文件

首次发现完整旧 `data/prototype_eng_research.dat` 且新目录从未初始化时，通过同一提交协议迁移，旧文件原字节保留。迁移完成写同级 `prototype_eng_research.migrated` 证据；之后新目录丢失或损坏不能退回过期旧快照。

首次初始化先在同级 staging 目录完整发布 pending，再原子发布为活动目录；发布前中止留下的 staging 不会被当作活动世界。已存在的活动目录缺少 meta 和 pending 时属于损坏，明确拒绝加载，不自动猜测并重建研究状态。不要删除新目录来尝试修复奖励或研究进度。

真实文件增量、迁移、删除、损坏及中断恢复测试和本机 IDEA 检查结果记录在[实施进度](implementation-status.md)。测试不代替游戏内多人、世界保存/重进或断电验收。
