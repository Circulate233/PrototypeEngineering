## 应保留的能力与应修正的旧实现

- 除用户明确取消或替换的部分外，全部 PM/PN 功能效果及多线程性能能力必须保留；未实现是迁移缺口，不是可选功能。每项实现必须先确认旧源码及其目的。
- 保留机器/进程组件与系统的装配关系、阶段调度、事件处理及生命周期边界。Java 25 重写可以简化类和包的组织，不能删掉扩展职责。
- 保留配方的可扩展需求集合、需求系统和进程状态。AEKey/AEKeyType 替换 PMKey 等资源身份；RecipeRequirementType 描述执行职责，二者不等价。
- 输入、输出和 FE 处理应成为内置需求处理的一部分，不能由执行器认识几个固定字段并排除其他需求。
- 旧 MachineInstanceImpl 的 runPhase 会捕获并记录系统错误后继续；旧 executeStage 的 rollbackAll 用 runCatching 吞掉回滚错误。这些行为与新项目的立即失败要求冲突，不迁入。
- RecipeRequirementSystem 注释存在“Blocked 应 commit”的表述，而 FactoryRecipeProcessorSystem 实际会对阻塞阶段整体回滚。新契约必须统一，不能同时复制矛盾说明。
- 旧进程组件恢复会跳过无法解析的组件类型，部分恢复代码吞异常。严格进程新格式要求全部 codec 覆盖并严格拒绝坏数据，已完成此前阶段验证；当前工作槽格式沿用该契约，已通过此前工作槽阶段验证，不提供旧存档静默升级。
- 当前部分收取/付款缓存可以作为资源操作研究材料，但不能替代需求阶段的提交契约；是否采用、如何参与回滚，必须在需求系统实现中明确验证。
- 存储 API 必须独立设计，不以 MEStorage 为核心契约；AE2 只提供资源类型及外部集成能力。目前已用 ResourceStorage/SlottedResourceStorage 和独立 SlottedResourceBuffer 替换原后端，预留/补偿的具体语义、旧账本 finalize 缺口和 PN 生命周期风险见[存储审查](storage-redesign.md)。这不代表 planned 调度集成已完成。

已迁移的组件实现沿用软依赖与 Kahn 排序，改用 fastutil 和独立不可变依赖快照；系统顺序使用显式 ID。重建派生系统索引避免组件替换后残留旧系统关系。图仍由单一执行所有者维护，未来通过调度屏障转移所有权；不以增加 volatile 标志冒充并发容器。

## 属性与时间线旧缺陷

- **扫描有效值二次放大与 int 边界。** [FactoryRecipeScanningSystem.parallelLimit](F:/clone/PrototypeMachinery/src/main/kotlin/impl/machine/component/system/FactoryRecipeScanningSystem.kt:128) 将机器已应用 modifier 的 PROCESS_PARALLELISM value 作为上限，再[写入进程 base](F:/clone/PrototypeMachinery/src/main/kotlin/impl/machine/component/system/FactoryRecipeScanningSystem.kt:208)，进程继承相同父 modifier 时再次计算倍率。例：机器 base=2、总乘数=2，选得有效量 4 后写成 overlay base，继承乘数使 value 变为 8。[二分查找成功分支](F:/clone/PrototypeMachinery/src/main/kotlin/impl/machine/component/system/FactoryRecipeScanningSystem.kt:179) 的 mid+1 在 mid=Int.MAX_VALUE 时递增溢出，可能使搜索边界失效。当前扫描使用 resolved base 保留本地 modifier、屏蔽父 modifier，并使用 long 搜索界；这些修正已通过此前扫描阶段构建与 MCP 检查。
- **流体随机刻索引停滞。** [FluidRequirementSystem.tickIndex](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/system/FluidRequirementSystem.kt:438) 把绝对工作进度 clamp 到 0..1 后乘 duration，progress 达到 1 就长期返回 duration，后续刻重复同一随机盐。新资源系统的 TICK 盐使用尚未推进的 long successfulTicks，阻塞重试可重复、成功刻之间可推进；不再使用该归一化假设。严格进程 codec 保存成功刻索引与 seed/调参，已完成此前阶段验证。
- **检查点零时刻遗漏及速度读取不一致。** [CheckpointRequirementSystem](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/component/system/CheckpointRequirementSystem.kt:49) 以 current < target && next >= target 触发（67），初始 current=target=0 时不触发 time=0；scaled 检查点自行读取 speed（55），处理器在需求执行后再读 speed（94），若阶段改变属性，两者可能采用不同推进量。新 time=0 检查点在 START 执行，其他检查点使用冻结 Tick 范围，子 TICK 全部回调保留同一上下文。严格进程 codec 恢复外层时间线与子状态；未保存正阈值嵌套触发刻的完整历史区间，不能据此完整推断全部历史激活。
- **volatile dirty 丢失失效及父实例引用过期。** [MachineAttributeInstanceImpl.value](F:/clone/PrototypeMachinery/src/main/kotlin/impl/machine/attribute/MachineAttributeInstanceImpl.kt:60) 计算后直接 dirty=false（66），计算期间另一次修改设置的 dirty=true 可被覆盖，缓存便保留旧值；volatile 字段和并发 modifier map 不组成完整计算协议。[OverlayMachineAttributeMapImpl](F:/clone/PrototypeMachinery/src/main/kotlin/impl/machine/attribute/OverlayMachineAttributeMapImpl.kt:64) 首次创建子视图时固定保存父 instance（67），父属性替换或后来补入时可继续读过期父实例。新属性通过 ID 查询稳定父层，不写缓存；并发父层修改仍必须受所有权屏障约束。
- **自定义 modifier 转数值导致行为丢失。** [AttributeModifierRequirementSystem.toInternal](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/component/system/AttributeModifierRequirementSystem.kt:93) 从 amount/operation 新建数值实现，未委托原 apply。新内部 ID 包装保留外部 AttributeModifier 的真实 operation/apply，不将接口扩展降成几种固定公式。
- **END 过早移除及交叠业务的整层回滚。** PM [属性 END](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/component/system/AttributeModifierRequirementSystem.kt:60) 获取阶段即移除 modifier（70），后续输出按降低后的值检查。新 END 只在所有业务 commit 成功后的 complete 清理。START 若用获取时的整层快照 rollback，会抹去较早需求在 commit 中做的属性变化，再执行其 rollback 可能双重撤销；新属性需求只撤销自己成功添加的 modifier，局部快照 API 不替代交叠事务的局部补偿。
- **阶段后更新状态会重放已完成效果。** PM [START 标记](F:/clone/PrototypeMachinery/src/main/kotlin/impl/machine/component/system/FactoryRecipeProcessorSystem.kt:46)、[TICK 进度](F:/clone/PrototypeMachinery/src/main/kotlin/impl/machine/component/system/FactoryRecipeProcessorSystem.kt:91) 和 END 移除槽位都在 execute 返回后更新。若资源/业务已经完成，而完成通知使 execute 抛错，外层状态仍未推进，下一次可能重放开始、每刻消耗或结束产出。新生命周期/进度在资源同阶段业务 commit 内写入且可补偿，通知报错不退回已跨过完成边界的状态；异常进程拒绝后续 tick，即使本次 rollback 成功也不恢复执行资格。宿主槽位移除已通过此前工作槽阶段验证，显式取消与失败清理源码已接入，当前异常入口拒绝及取消阶段仍已通过本阶段构建与 MCP 检查。

## 高级需求旧实现缺陷与迁移边界

- **选择器 START 重试漏消耗风险。** [SelectiveRequirementSystem](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/component/system/SelectiveRequirementSystem.kt:49) 在 acquisition 时写 selectedIndex（56），START rollback 只撤销 modifier 和子事务（95–99），不撤销选择索引。后续需求阻塞使输入回滚后，再次 START 因既有索引直接成功，可能跳过已回滚的输入。其 END rollback 还会清除已生效 modifier（150–152），输出阻塞后的重试会丢失效果。新 START 局部撤销 provisional selection，END 仅在 complete 清属性/自有 overlay；阻塞重试、overlay 生命周期与自有效果保存恢复均已完成此前阶段验证。
- **流体 TICK 模拟重复使用余额/容量。** [输入模拟](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/system/FluidRequirementSystem.kt:198)及输出模拟（214）逐条模拟，未聚合也未为前项预留。同 key 两项各需 100、可用量 150 时，两项都可通过检查而实际执行失败。迁移须按确定 key 聚合或让整批预留覆盖全部需求。
- **随机输出最大数量检查不能证明容量安全。** [worstCaseKeys](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/system/ItemRequirementSystem.kt:499) 只取数量最大的 pickCount 个 key；能容纳这些 key 不代表能容纳另一些随机 key，槽位和 key 限制也不能由总量推导。新实现按实际确定的 AEKey/数量预留，保留加权效果并修正此容量假设；非平凡池的 planned 工作预算仍待实现。
- **动态候选先截断再排序。** [enumerateDynamicCandidates](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/system/ItemRequirementSystem.kt:440) 达到上限便停止枚举（443–452），随后才排序（457）；来源遍历顺序可能影响候选子集。新实现全扫描匹配后按完整规范身份排序，再截断；结果上限不限制总工作成本，后续 planned 仍须预算。
- **旧补偿忽略实际恢复量。** [rollbackExtracted/rollbackInserted](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/system/ItemRequirementSystem.kt:513) 调用 unchecked 插入/提取但忽略返回数量；流体也有同类代码。不能复制“尽力退回”便宣称资源守恒。新需求应使用已有预留/补偿协议，并让无法完成的补偿显式失败；不能先公开输出再依赖撤回仍可被外部取得的资源。
- **逐需求完成不能替代整阶段完成。** 旧阶段分派先 acquisition 后逐事务 commit；资源、FE 与业务/选择状态须具有共同的完成和失败边界，不能让较早需求独自最终完成后仍遇到后项失败。新同步协调已接入，生命周期/进度、选择状态、overlay 局部句柄和子令牌归同一补偿/完成边界并通过此前验证；进程与工作槽只允许稳定边界保存，真实 planned 提交协议未完成。
- **旧 planned 投影覆盖不足。** [ItemRequirementComponent.snapshot](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/ItemRequirementComponent.kt:42)及[FluidRequirementComponent.snapshot](F:/clone/PrototypeMachinery/src/main/kotlin/impl/recipe/requirement/FluidRequirementComponent.kt:52) 拒绝全部非空 properties，投影仅涉及固定输入及流体每刻输入。概率、模糊、动态、随机、选择与 overlay 仍需要显式快照、有效定义和状态投影契约，不能因固定消耗可投影就宣称完整 planned 迁移完成。

取消/终态所有权和机器宿主生命周期已完成本阶段验证；下一步接实际世界结构宿主和 planned 适配。需求定义和系统可跨进程共享，变化必须归各进程；真实调度继续遵守 PM 的两次 join、稳定 affinity lane 与 PN owner/epoch/预算边界。以上是依赖排序，所有高级效果和外部扩展职责仍在保留范围。
