## 研究站已确认的内容

界面显示当前研究、目标等级、研究时间进度、普通资源需求、网络资源占用与累计进度，以及队伍共享研究队列。队列支持调整顺序、设为当前研究和移出队列。切换与移出都保留该队伍对应研究目标等级的进度，重新入队继续使用；队列不拥有或删除研究进度。

研究时间 T 使用 long，单位为 tick，表示单站基准工作量。每台实际工作的研究站每服务器 tick 贡献 1 tick 工作量，多站贡献相加，累计到 T 后停止增加。例如 T=100，两台站在材料、网络资源、站点速率和能源均满足时，可用 50 个服务器 tick 完成。已累计时间必须与各项资源进度分别保存，只有时间与全部资源需求均完成，研究才完成。

普通资源只允许按总量定义；界面逐项显示“当前可用 / 剩余需求”，实际扣取多少就同步减少多少剩余需求。当前可用必须汇总同队所有研究站当前可用于该研究的资源，不能只统计打开界面的研究站或当前取得并发的研究站。显示值取所有站可用量之和与剩余需求的较小值，最大显示为 x/x；例如合计可用 72、剩余需要 5，显示 5/5，合计可用 6、剩余需要 10，显示 6/10。剩余需求属于队伍共享的研究目标；多个站共同供料时，必须把实际扣取量累计到同一剩余需求，禁止每站重复支付整份总需求。

网络资源可按每 tick 上限 u 或总量 R 定义：R=u×T，u=R÷T。u 和 R 均为 double；T 使用 long，按总量定义时禁止把除法结果取整。定义时的 u 按单站计算，多站合计上限随实际参与站数增加，同时受各站自身资源速率限制。总需求 R 始终固定，不随站数增加。界面显示当前研究参与站的合计占用和合计有效上限，以及各资源的“已累计 / 总需求”。手动研究禁止网络资源需求。

各项网络资源独立累计，可用供给不足时允许部分推进；每 tick 数值是上限，不是必须全部满足的启动门槛。每项仍必须最终达到实际总量，已经达标的资源停止占用，其他资源可继续追赶。时间达到 T 后，也必须等待尚未达标的资源。

普通资源按比例开放推进范围，任意网络资源达到已付款项允许的百分比上限时，尝试支付下一份普通资源。各资源种类等权累计，开放比例为各项已支付比例之和除以资源种类数；允许一段只扣 A，下一段再扣 B，也允许先支付有库存的其他资源。例如 A 总需 2、B 总需 10、C 总需 100，扣 1 个 A 开放 1/6，扣完 A 开放 1/3。禁止要求整套资源共同支付或取各项付款比例的最低值。缺少下一份材料时，已经达到上限的网络资源等待，落后的资源仍可推进到该上限；已支付的材料不得再次扣取。没有网络资源需求时，按研究时间进度触发材料分段支付。时间累计也受已支付材料比例限制。

研究使用与其他设备相同的网络预算，研究站最低优先级。保留多个研究站共同参与；每台实际工作的研究站只占用一个并发。界面不显示本站并发。

## 正式界面

2026-11-15 正式 Java 界面已按 [设备界面改版](device-gui-redesign.md) 和覆盖后的 [研究站预览](previews/research-station.html) 实现。游戏内尺寸为 384×288，无玩家背包。标题副行显示 FTB 队伍名称；顶部显示当前研究、等级、状态标签、工作量、参与站数和百分比进度条。没有当前研究时只居中显示一次“暂无研究”。

左侧材料为固定五列图标格，每格 32×30，简写的当前可用/剩余需求显示在图标下方，缺料显示红色，悬停显示材料名称和完整数量。网络资源显示占用/上限、累计细条、累计数值/总需求及百分比，完成后标明“已完成”。左侧可见高度为 180，超出时使用本地滑块，只绘制可见格和资源行。

右侧五项队列采用卡片行，依次显示序号、名称和等级，队首有绿色竖条及“进行中 · Lv.N”。队列图标列按改版说明允许的方案省略。上移和下移使用 AE 原生箭头图标，四个按钮共同使用 AE 文字按钮的背景与点击处理。按钮高 13、箭头 8×8、标签内容高 6，四项共用一条文字基线与下边缘；禁用时整颗按钮淡化，按确认预览保留浅色字。

正式界面从服务器读取当前研究和队列。顶部百分比表示时间工作量，各网络资源分别显示累计条；时间达到 100% 后仍需等待所有资源达标。定义随队首切换发送，随后仅通过 AE 自定义包同步变化的行索引与数值，稳定时不发包。新容器获取完整基线，客户端缓存名称和格式化数值。文字标题居左、数值靠右，按钮沿 AE 原生样式。

队伍 ID 仅在服务器用于队列操作权限校验；显示用队名通过 AE GuiSync 单独同步。当前研究名称、等级和状态分别保留显示宽度，标题、队名、工作量与研究名称截断时可悬停查看完整文字。

## 数据库界面

2026-11-16 按已确认的 [数据库预览](previews/data-center.html) 完成正式 Java 布局，尺寸为 384×290。左侧显示本物理数据库的已存研究并支持移出；右侧复用材料槽、箭头和输出槽，通过按钮切换研究下载与研究导入；底部显示完整玩家背包。

默认入口已接入 `ContainerDataCenter` 和 `GuiDataCenter`，操作槽直接使用 `MachineDataCenterStorage.transfers()`。列表可见五行，超出后使用 AE 原生滑块；图标、名称、等级和底部二次确认各占固定区域。标题及数值按原字号绘制，长文本截断后通过悬停查看完整内容。输入输出槽和 27+9 玩家背包沿用原生槽位交互，实际输出优先于半透明候选。

标题栏显示数据库等级、已存条目数与容量及启用状态。左侧列出已存研究的图标、名称和已存等级，长名称省略并在悬停时显示全名及最高等级。左侧选中一项后，底部显示“移出数据库”按钮，点击后改为“确认移出”和“取消”两个按钮并提示移出不影响队伍研究等级；确认后数据库删除该条目、释放一格容量。世界存档待确认或没有操作权限时按钮禁用。

右侧“选择研究”保留 AE 原生按钮外观，通过容器以当前物理数据库构造并打开[研究总览](research-overview.md#两种构造)。总览可以选择任意队伍已完成、首级研究阶级不高于该数据库阶级的研究，不要求研究已存于该数据库；选定或退出后返回原数据库，返回按钮使用 AE 原生 `Icon.BACK` 图标按钮。`specialOnly` 不能作为下载目标。选择只确定目标研究，下载配方、所需材料、来源等级和数据库已存等级仍由服务端判定并在操作区显示实际状态。右侧显示研究名称、研究阶级与研究费用，禁止添加下载来源或可选择的下载等级。

自定义下载配方定义单件输入、单种输出、研究要求和等级费用，研究定义不承担下载费用，普通输出数量由配方决定。默认存盘下载直接使用物品接口，每次支付来源 1 级并编码所选研究的 1 级，不需要注册配方；即使研究支持多级，也不提供等级或数量选择。费用显示必须使用服务端本次付款对队伍可见研究等级的实际影响：没有掉级时显示“无”，发生掉级时显示“队伍降低 N 级”。队伍可见等级未降低不能免除本次来源付款。

材料槽允许放入物品。匹配的配方可执行且输出槽为空时，显示半透明产物预览并加深箭头；点击预览消费一件输入，产物进入输出槽，左键或 Shift 点击取出。输出槽禁止放入；有实际产物时不生成下一份预览。没有匹配配方或回调未提供输出时，输出槽为空，不添加无对应输出的错误提示。权限、保存待确认、来源等级或材料阶级不足仍显示实际业务状态。

“导入数据库”按钮切换右侧的同一操作区，按钮文字随模式改为“下载到物品”。导入配方从输入物品确定研究，复用同一箭头与输出槽，不再打开研究总览选择输入内容。普通导入配方允许自定义单输入和单输出；存盘导入每份向数据库累加 1 级对应研究，并输出空存盘。例如已存 2 级，再导入一份变为 3 级；达到研究最高等级或目标阶级、容量及互斥要求不满足时不得付款。导入不扣队伍研究来源等级，费用显示“无”。

云端直接写数据库继续由云端调用现有下载方法执行，数据库界面不承担该入口，不改变云端写库规则。

界面底部显示完整玩家背包（27 格主背包和 9 格快捷栏），沿用原生槽位交互：左键拿起、放下和交换，右键拆半和逐个放入，Shift 点击在背包与操作材料槽之间转移。输入槽和输出槽属于物理数据库，物品及交易回执随机器存储保存；切换模式与关闭界面不丢弃物品。

下载和物品导入要求本队当前活动物理数据库（`ITEM_ONLY` 同样绑定活动数据库 UUID）。非活动数据库、世界存档待确认和无操作权限时，已存列表与背包保留，操作区不显示预览；无查看权限时不显示研究，选择与移出不可用；数据库为空时左侧显示空列表提示。同队非活动库仍可按独立移出权限清理条目，移出未完成的导入回执涉及的研究必须等待该交易完成。

自定义配方注册、默认存盘操作、服务器预览与执行、数据库移出、输入输出库存保存及恢复和 JEI 接线已完成。正式 GUI 已接入服务端候选及执行方法，通过输入物品进入导入流程，通过总览选择返回进入下载流程；操作槽属于原物理数据库，在界面之间切换时保留物品。必须读取服务端冻结的候选输出与实际费用，点击时重新捕获当前权限、物理数据库及原输入；禁止在客户端推算输出或点击时再次调用纯输出回调，否则会改变已经预览的候选。实际实现与验证记录见 [implementation-status.md](implementation-status.md)。

JEI 为自定义研究下载和自定义研究导入生成常规输入 → 输出页面，并简要标明所需或导入的研究及研究消耗。默认存盘下载与导入不注册、不参加 JEI；使用方自行说明存盘用法。没有匹配输出属于正常配方查询结果，不承担报错职责。
