# 研究 GUI

2026-11-14 研究站正式界面与后台推进已按用户批准的布局和规则实现。研究目录、奖励、数据库、遗忘与管理员界面继续延缓。

## 研究站已确认的内容

界面显示当前研究、目标等级、研究时间进度、普通资源需求、网络资源占用与累计进度，以及队伍共享研究队列。队列支持调整顺序、设为当前研究和移出队列。切换与移出都保留该队伍对应研究目标等级的进度，重新入队继续使用；队列不拥有或删除研究进度。

研究时间 T 使用 long，单位为 tick，表示单站基准工作量。每台实际工作的研究站每服务器 tick 贡献 1 tick 工作量，多站贡献相加，累计到 T 后停止增加。例如 T=100，两台站在材料、网络资源、站点速率和能源均满足时，可用 50 个服务器 tick 完成。已累计时间必须与各项资源进度分别保存，只有时间与全部资源需求均完成，研究才完成。

普通资源只允许按总量定义；界面逐项显示“当前可用 / 剩余需求”，实际扣取多少就同步减少多少剩余需求。当前可用必须汇总同队所有研究站当前可用于该研究的资源，不能只统计打开界面的研究站或当前取得并发的研究站。显示值取所有站可用量之和与剩余需求的较小值，最大显示为 x/x；例如合计可用 72、剩余需要 5，显示 5/5，合计可用 6、剩余需要 10，显示 6/10。剩余需求属于队伍共享的研究目标；多个站共同供料时，必须把实际扣取量累计到同一剩余需求，禁止每站重复支付整份总需求。

网络资源可按每 tick 上限 u 或总量 R 定义：R=u×T，u=R÷T。u 和 R 均为 double；T 使用 long，按总量定义时禁止把除法结果取整。定义时的 u 按单站计算，多站合计上限随实际参与站数增加，同时受各站自身资源速率限制。总需求 R 始终固定，不随站数增加。界面显示当前研究参与站的合计占用和合计有效上限，以及各资源的“已累计 / 总需求”。手动研究禁止网络资源需求。

各项网络资源独立累计，可用供给不足时允许部分推进；每 tick 数值是上限，不是必须全部满足的启动门槛。每项仍必须最终达到实际总量，已经达标的资源停止占用，其他资源可继续追赶。时间达到 T 后，也必须等待尚未达标的资源。

普通资源按比例开放推进范围，任意网络资源达到已付款项允许的百分比上限时，尝试支付下一份普通资源。各资源种类等权累计，开放比例为各项已支付比例之和除以资源种类数；允许一段只扣 A，下一段再扣 B，也允许先支付有库存的其他资源。例如 A 总需 2、B 总需 10、C 总需 100，扣 1 个 A 开放 1/6，扣完 A 开放 1/3。禁止要求整套资源共同支付或取各项付款比例的最低值。缺少下一份材料时，已经达到上限的网络资源等待，落后的资源仍可推进到该上限；已支付的材料不得再次扣取。没有网络资源需求时，按研究时间进度触发材料分段支付。时间累计也受已支付材料比例限制。

研究使用与其他设备相同的网络预算，研究站最低优先级。保留多个研究站共同参与；每台实际工作的研究站只占用一个并发。界面不显示本站并发。

## 正式界面

2026-11-15 材料区调整要求：材料改为固定四列图标网格，每个图标右下角显示当前可用/剩余需求的简写数量；悬停显示材料名称和完整数量。材料高度按网格行数计算，网络资源、顶部研究进度、队列及底部参与站数沿现有布局。对应预览已更新，正式 Java 界面尚未修改，等待核对后接入。

[研究站预览](previews/research-station.html) 已获批准，正式界面使用同样的 AE 配色、原生按钮和边框，游戏内尺寸为 384×288，无玩家背包。顶部显示当前研究和百分比进度条；左侧显示普通资源、网络占用及累计进度，超出高度时使用本地滑块；底部显示参与站数；右侧保留五项队列及上移、下移、设为当前、移出四个按钮。

正式界面从服务器读取当前研究和队列。顶部百分比表示时间工作量，各网络资源分别显示累计条；时间达到 100% 后仍需等待所有资源达标。定义随队首切换发送，随后仅通过 AE 自定义包同步变化的行索引与数值，稳定时不发包。新容器获取完整基线，客户端缓存名称和格式化数值。文字标题居左、数值靠右，按钮沿 AE 原生样式。

2026-11-15 删除标题右侧队伍 ID；该值仅留在服务器用于队列操作权限校验，不再发送给客户端。没有当前研究时顶部只显示一次“暂无研究”，无权限时显示对应提示。当前研究名称、等级和状态分别保留显示宽度，队首标记及百分比使用统一的文字行高。

2026-11-13 删除研究 GUI 时保留的研究、队列、奖励、数据库、下载、研究盘及权限/持久化后台仍在；旧 GUI 的已实现或待验记录不作为本次完成依据。
